# 일일 마감

> ## 검수자가 **직접 말했을 때만** 부른다
>
> "일일마감"·"마감"·"퇴근" 같은 말을 **그 자리에서 들었을 때만** 시작한다.
>
> **계획서에 적어두고 스스로 발동하지 않는다.** 2026-08-07에 아침 계획의 마지막 블록으로 "일일마감"을 넣어두고, 계획이 승인됐다는 이유로 11:56에 실행했다. **하루는 그 뒤로 다섯 시간 넘게 이어졌고**, 오전만 담은 데일리보고와 바이브로그가 남아 검수자를 혼란스럽게 했다. 게다가 나는 그것을 "검수자가 마감이라고 했을 때"라고 잘못 말했다.
>
> **하루가 끝났는지는 검수자가 안다.** 계획 승인은 절차의 승인이지 "지금 하루를 닫아도 된다"는 뜻이 아니다.
>
> 오늘 작업이 일단락된 것 같으면 **마감하겠다고 묻지 말고 그냥 다음 일을 하거나 멈춘다.** 필요하면 검수자가 말한다.

**"일일마감" 한 마디에 여기까지 끝난다.** 검수자가 절차를 기억할 필요가 없게 만드는 것이 이 스킬의 목적이다.

산출물은 `98. 일일 마감/` 아래 셋이다.

| 파일 | 주기 | 재호출 시 | 무엇 |
|---|---|---|---|
| `YYYYMMDD-HHMM-session-log.md` | 수시 | **새 파일** | 사실과 숫자. **나머지 둘의 원본** |
| `YYYYMMDD-daily-report.md` | 하루 1개 | **갱신** | 검수자가 읽고 판단할 것 |
| `YYYYMMDD-vibe-log.md` | 하루 1개 | **갱신** | 숫자로 안 남는 것 |

세션로그만 갱신하지 않고 새로 만든다. **그 시점의 앎을 보존해야** 하기 때문이다 — 오후에 뒤집힌 오전의 판단이 지워지면 다음에 같은 함정을 못 본다.

---

## 0. 날짜와 시각을 실제로 확인한다

기억이나 추측으로 쓰지 않는다.

```bash
date "+%Y%m%d %H%M"
```

---

## 1. 오늘 세션로그를 모은다

```bash
ls "98. 일일 마감/$(date +%Y%m%d)"-*-session-log.md
```

### 마지막 세션이 아직 안 적혔으면 먼저 적는다

마감 직전까지 한 작업은 대개 세션로그에 없다. **[session-log](../session-log/SKILL.md) 스킬로 먼저 남기고** 나머지를 진행한다. 이걸 건너뛰면 데일리보고를 기억으로 쓰게 되고, 그때 숫자가 틀린다.

### 오늘 세션로그가 하나도 없으면

하루 종일 세션로그를 안 남긴 것이다. 그날 한 일을 **대화와 파일 변경 이력에서 복원**해 세션로그부터 만든다. 다만 **복원한 숫자는 "복원값"으로 표시**한다 — 실측한 것과 기억해낸 것을 섞으면 안 된다.

---

## 2. 상태를 실제로 점검한다

보고에 쓸 값을 **추측하지 말고 확인한다.**

```bash
# 문서 정합성과 현재 버전
PYTHONUTF8=1 python "99. 작업 스크립트/검증.py"

# 최신 스냅샷
ls -d "백업"/v*/ | tail -3

# 작업본과 납품물의 시각 차이
ls -la *.mp3 *.mp4 "99. 작업 스크립트"/*.wav 2>/dev/null
```

여기서 **작업본과 납품물이 어긋난 상태**가 자주 잡힌다. 예: `전곡화성.wav`는 새 필터인데 납품 mp3는 옛 필터. 이런 것이 데일리보고 2절의 재료다.

---

## 3. 데일리보고를 쓴다

[daily-report](../daily-report/SKILL.md) 스킬을 따른다. 요지만:

- 그날 세션로그 **전부**를 재료로 쓴다
- **2절 "검수자가 알아야 할 것"이 핵심**이다. 일정 변동, 판정 대상과 현재 상태의 어긋남, 누적 신호, 막힌 것
- 나쁜 소식을 묻지 않는다
- 4절 다음 작업은 **하나만** 고른다

---

## 4. 바이브로그를 쓴다

[vibe-log](../vibe-log/SKILL.md) 스킬을 따른다. 요지만:

- **실수를 모양끼리 묶는다.** 다섯 번 틀렸는데 셋이 같은 모양이면 고칠 것은 하나다
- 누적 신호를 본다 — 오늘 처음이 아닌 것
- 순탄한 날은 **왜 순탄했는지**를 쓴다. 억지로 반성거리를 만들지 않는다
- 규칙으로 뽑히면 인용구로 남긴다

---

## 5. 마무리 확인

- [ ] `date` 로 확인한 실제 날짜·시각을 썼다
- [ ] 세션로그 · 데일리보고 · 바이브로그 셋 다 있다
- [ ] 파일명이 `YYYYMMDD-` 접두사 + 영어다. 언더바 없음
- [ ] 데일리보고에 **검수자가 알아야 할 것**이 실제로 들어 있다
- [ ] 세션로그의 "이어서 할 때 알아야 할 것"이 다음 세션에 충분한가
- [ ] 같은 사실을 두 문서에 중복해 쓰지 않았다
- [ ] `검증.py` 결과를 보고에 반영했다
- [ ] 답변 끝에 `작성 일자: YYYY-MM-DD`

---

## 이 폴더는 프로젝트 버전 체계 밖이다

**중요하다.** `98. 일일 마감/`의 문서는 **명세가 아니라 일지**다.

| | 프로젝트 문서 (`00`~`08`) | 일일 마감 |
|---|---|---|
| 버전 | 전체 하나 (v1.11 등) | **없음** |
| 스냅샷 | `백업/vN.N .../` | **안 넣는다** |
| `검증.py` | 검사 대상 | 루트 `*.md`만 훑으므로 **안 잡힌다** |
| 고칠 때 | `doc-revise` 절차 | 그냥 쓴다 |

일일 마감 문서를 고쳤다고 **프로젝트 버전을 올리지 않는다.** 스냅샷도 만들지 않는다. 반대로 프로젝트 문서를 고쳤으면 그건 `doc-revise` 절차를 그대로 밟아야 한다 — 마감 중이라고 예외가 되지 않는다.

## 하지 말 것

- 날짜·시각을 추측해서 쓰기
- 세션로그 없이 데일리보고부터 쓰기
- 세 문서에 같은 사실 반복
- 일일 마감 문서에 프로젝트 버전 매기기
- `백업/` 스냅샷에 넣기
