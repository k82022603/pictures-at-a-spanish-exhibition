# 문서 개정 절차

이 프로젝트는 문서 8개가 **같은 수치를 공유**한다(사진 253장, 총 기간 28.5일, 실측값 등). 그래서 프로젝트 전체에 버전 하나를 붙이고, 고칠 때마다 전체 스냅샷을 남긴다. 한 문서만 고치고 끝내면 세트가 깨진다.

절차의 정본은 `04. 문서 개정 이력.md` 5장이다. 이 스킬은 그 절차를 실행 가능한 형태로 풀어 쓴 것이다.

## 0. 먼저 확인

```bash
cd "<프로젝트 루트>"
python "99. 작업 스크립트/검증.py"    # 손대기 전에 통과 상태인지 본다
```

**이미 실패하고 있으면 먼저 그것을 고친다.** 내가 만든 실패와 원래 있던 실패를 섞으면 원인을 못 찾는다.

현재 버전은 `04. 문서 개정 이력.md` 머리 표에서 읽는다. `CLAUDE.md` 3절에도 적혀 있지만 **정본은 04**다.

## 1. 스냅샷 — 수정 **전에**

```bash
mkdir -p "백업/vN.N (YYYY-MM-DD) 요약"
cp *.md .gitignore "백업/vN.N (YYYY-MM-DD) 요약/"
```

- `vN.N`은 **이 작업의 결과가 될 새 버전**이다. 지금까지 전부 그렇게 해 왔다 — `백업/v1.6 (2026-08-05) 유튜브 검토 영상/`은 v1.6 작업의 결과물이다
- 요약은 **무엇을 한 작업인지** 한 마디로. 예: `작곡 계획`, `전곡 화성 진행`, `유튜브 검토 영상`
- `*.md` glob이 `CLAUDE.md`를 잡지만 `.gitignore`는 안 잡힌다. 명시적으로 넣는다
- `README.txt`에 한두 줄로 이 스냅샷이 무엇인지 남긴다

## 2. 수정 — 기존 내용을 지우지 않는다

**이것이 이 프로젝트의 제1 규칙(R3)이다.** 판단이 바뀌었으면:

- 원문을 **그대로 둔다**
- 뒤에 `### 개정 — <무엇> (vN.N)` 절을 덧붙인다
- 그 절에 **원안 / 변경안 / 왜 바꿨는지**를 적는다. 표로 나란히 놓으면 읽기 쉽다
- 폐기한 것은 취소선이나 "폐기했다. 이유는 …절에 있다"로 남긴다

좋은 예가 세 곳에 있으니 형식을 참고한다.

| 문서 | 절 | 무엇을 뒤집었나 |
|---|---|---|
| `02. AI 영상 생성 기술 검증 계획서` | 7.4 | "없던 인물 추가 금지" → 서사 도입으로 범위 재정의 |
| `03. 스토리라인과 등장인물` | 5장 개정 절 | E 프리지안 → D 프리지안 |
| `05. 코드 진행 스케치 검토서` | 9.2 · 9.3 | 조성 밖 음 정리, E♭ 장조 → E♭ 리디안 |

원문을 지웠다면 나중에 "왜 이렇게 결정했더라"를 알 수 없다. 실제로 02 문서 7.4절은 원문을 남긴 덕에 **뒤집힌 게 아니라 원래 안전하다고 본 범주를 확장한 것**임이 드러났다.

## 3. 대조 — 바뀐 수치가 다른 문서에도 있는가

`99. 작업 스크립트/검증.py` 상단 `SHARED` 딕셔너리가 공유 수치 목록이다. 여기 있는 값을 고쳤으면 **모든 문서에서 함께 고치고 `SHARED`도 고친다.**

수치 말고도 잘 어긋나는 것들:

- **악장 구성표** — `00` 기획서, `자막생성.py`의 `MOV`, `검증화성.py`의 `MOV`에 같은 내용이 세 벌 있다
- **백로그 항목** — `01` 문서와 `CLAUDE.md` 7절
- **확정 음악 설계** — `CLAUDE.md` 6절과 `전곡화성.py` 상단 상수
- **실측값** — `05` 문서 9·10장과 `CLAUDE.md` 7절

## 4. 버전 — 각 문서 머리 표와 개정 이력

수정한 문서마다 (1) 머리 표 버전 갱신, (2) `### 개정 이력` 표에 행 추가.

**빠뜨리기 쉬운 것 — 직전 버전 행의 굵게 표시를 푼다.** 최신 행 하나만 굵어야 한다.

```
| v1.5 | 2026-08-05 | ... |          ← 굵게 표시를 풀었다
| **v1.6** | 2026-08-05 | ... |      ← 새로 추가, 이것만 굵게
```

그리고 **손대지 않은 문서도 머리 표 버전은 올린다.** "v1.6끼리 맞는 세트"가 성립해야 한다. 실질 변경이 없으면 개정 이력에 `변경 없음 (프로젝트 버전 동기화)`로 남긴다.

```bash
python - <<'PY'
import io, glob
OLD, NEW = 'v1.6', 'v1.7'
OLDD, NEWD = '2026-08-05', '2026-08-06'
for f in glob.glob('*.md'):
    t = io.open(f, encoding='utf-8').read()
    t = t.replace('| **버전** | **%s** (%s) |' % (OLD, OLDD), '| **버전** | **%s** (%s) |' % (NEW, NEWD))
    t = t.replace('| 현재 버전 | **%s** (%s) |' % (OLD, OLDD), '| 현재 버전 | **%s** (%s) |' % (NEW, NEWD))
    t = t.replace('버전 **%s** (%s) · 작성 Claude' % (OLD, OLDD), '버전 **%s** (%s) · 작성 Claude' % (NEW, NEWD))
    io.open(f, 'w', encoding='utf-8').write(t)
print('버전 표기 갱신')
PY
```

문서별 버전 표기 위치가 세 가지다.

| 문서 | 형식 |
|---|---|
| `00`~`06` | 머리 표 `\| **버전** \| **vN.N** (날짜) \|` |
| `04` | 머리 표 `\| 현재 버전 \| **vN.N** (날짜) \|` |
| `07. 작곡 계획` | 머리 표가 없다. 본문 상단 `버전 **vN.N** (날짜) · 작성 Claude` |
| `CLAUDE.md` | 3절 본문과 파일 끝 한 줄. **`검증.py` 5번 검사에서 제외**되어 있으니 손으로 고친다 |

## 5. 대장 — `04. 문서 개정 이력.md` 세 곳

한 곳만 고치기 쉬운데 **세 곳**이다.

| 위치 | 무엇 |
|---|---|
| 2장 "현재 위치" | `v1.5 → v1.6 → v1.7  ← 지금` 화살표 갱신 |
| **3장 전체 개정 이력** | 행 추가. 변경 내용 · **영향받은 문서 번호** · 스냅샷 유무 |
| **4장 문서별 반영 현황** | 실제로 내용이 바뀐 문서의 "최종 내용 변경" 열 갱신 |

2장 본문에 `"v1.6은 언제나 v1.6끼리 맞는다"`, `"머리 표에는 v1.6으로 적힌다"` 같은 문장이 버전 숫자를 품고 있다. 함께 고친다.

## 6. 검증 — 반드시

```bash
python "99. 작업 스크립트/검증.py"
```

6종 검사다. **6번이 스냅샷 누락을 자동으로 잡으므로 1단계를 잊어도 여기서 걸린다.**

| # | 검사 | 흔한 실패 원인 |
|---|---|---|
| 1 | 표의 열 수와 구분선 | 셀 안에 세로줄 문자를 쓰면 열이 어긋난다 |
| 2 | 내부 링크가 실제 파일을 가리키는가 | 파일명에 공백이 있으므로 대괄호 제목 + 소괄호 안 꺾쇠로 감싼다. **본문에 링크 예시를 그대로 적으면 실제 링크로 오인된다** — 설명할 때는 코드 표기로 쪼개 쓴다 |
| 3 | 목차 앵커 ↔ 헤딩 | 절을 추가하고 목차를 안 고쳤다. 앵커는 소문자·공백→하이픈·특수문자 제거 |
| 4 | 공유 수치 일치 | 3단계를 건너뛰었다 |
| 5 | 전 문서 버전 일치 | 4단계에서 일부 문서를 빠뜨렸다 |
| 6 | 최신 스냅샷 ↔ 현재 문서 | 스냅샷을 안 남겼거나, 남긴 뒤에 더 고쳤다 |

**6번이 실패하면 스냅샷을 다시 덮어쓴다** — 수정이 끝난 상태가 그 버전의 정본이다.

```bash
cp *.md .gitignore "백업/vN.N (날짜) 요약/"
python "99. 작업 스크립트/검증.py"
```

## 완료 체크리스트

- [ ] 기존 내용을 지우지 않았다. 뒤집힌 판단은 "개정" 절에 **무엇이 왜** 적었다
- [ ] 공유 수치를 전 문서에서 함께 고쳤다. `SHARED`도 고쳤다
- [ ] 전 문서 머리 표 버전 갱신. **직전 행 굵게 표시 해제**
- [ ] `04` 문서 2·3·4장 세 곳 모두 갱신
- [ ] `CLAUDE.md` 3절·끝줄 버전, 7절 "현재 위치"도 사실과 맞는가
- [ ] `검증.py` 통과
- [ ] 답변 끝에 `작성 일자: YYYY-MM-DD`

## 버전을 올리지 않는 경우

오탈자·서식만 고쳤으면 버전을 올리지 않고 스냅샷도 만들지 않는다. `04` 문서 3장 이력에 `(서식)`으로만 남긴다.

되돌린 경우도 **앞으로 흐르는 새 버전**으로 기록한다. v1.6에서 v1.5로 돌아갔다면 그것은 v1.5가 아니라 v1.7이다. 이력이 앞으로만 흐르게 두는 편이 나중에 헷갈리지 않는다.

## MAJOR를 올리는 경우

검수 게이트 통과 시에만 MAJOR를 올린다. G1 기획 승인이 v1.0이었다. **G2 데모 승인이 v2.0이 된다.**
