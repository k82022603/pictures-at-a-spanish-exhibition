# 데일리보고

**검수자가 읽고 판단할 것만 적는다.** 경위와 실측 전문은 세션로그에 있고, 여기서는 링크만 건다.

하루에 하나. 그날 세션로그 전부를 재료로 쓴다.

## 어디에 쓰나

```
98. 일일 마감/YYYYMMDD-daily-report.md
```

시각은 붙이지 않는다 — 하루에 하나뿐이다.

## 0. 시각을 실제로 확인한다

```bash
date "+%Y-%m-%d %H:%M"
```

## 1. 모드 판정 — 파일이 이미 있는가

```bash
ls "98. 일일 마감/$(date +%Y%m%d)-daily-report.md" 2>/dev/null
```

### 있으면 — 갱신 모드

마감 뒤에 작업이 더 이어진 경우다. **새 파일을 만들지 않는다.**

| 절 | 갱신 방법 |
|---|---|
| 머리 표 | 덮어쓴다 (버전·렌더 횟수는 누적값) |
| 1. 끝난 것 | 이어서 추가 |
| 2. 알아야 할 것 | 이어서 추가. **철회된 항목은 지우지 말고 `✔ 해소 (…)`로 표시** |
| 3. 미결 · 이월 | 끝난 행에 `✔` 표시하고 새 행 추가 |
| 4. 다음 작업 | 덮어쓴다 |
| 5. 검수 요청 | 이어서 추가 |

**끝에 `**갱신** HH:MM — 무엇이 늘었나` 한 줄을 남긴다.** 검수자가 이미 읽은 보고서라면 무엇이 새로 붙었는지 알아야 한다.

### 없으면 — 생성 모드

아래 절차대로.

## 2. 그날 세션로그를 전부 읽는다

```bash
ls "98. 일일 마감/$(date +%Y%m%d)"-*-session-log.md
```

기억으로 쓰지 않는다. **세션로그에 없는 숫자는 데일리보고에도 쓰지 않는다.** 없으면 다시 재거나, 없다고 적는다.

## 뼈대

```markdown
# 데일리보고 YYYY-MM-DD

**검수자가 읽고 판단할 것만 적는다.** 경위와 실측 전문은 [세션로그](<...>)에 있다.

| 항목 | 내용 |
|---|---|
| 프로젝트 버전 | vA.B → vC.D |
| Phase | |
| 전곡 렌더 | N회 |
| 검증 상태 | |

## 1. 오늘 끝난 것
## 2. 검수자가 알아야 할 것
## 3. 미결 · 이월
## 4. 다음 작업
## 5. 검수 요청
```

## 각 절

### 1. 오늘 끝난 것

**완료된 것만.** 진행 중인 것은 3절로. BL 번호·WBS 번호를 함께 적어 백로그와 대조되게 한다.

한 줄 요약 + 근거 숫자. "BL-24b 완료"가 아니라 "BL-24b 완료 — 발진 음정 3.9센트, 회귀 없음(경직됨 0.941로 v1.5와 동일)".

### 2. 검수자가 알아야 할 것 ★

**이 절이 데일리보고의 존재 이유다.** 검수자가 모르면 잘못 판단하게 되는 것을 적는다.

들어가야 할 전형:

| 종류 | 예 |
|---|---|
| **일정이 바뀐 것** | 총 기간 28.5 → 30.0 작업일. 승인된 결정의 결과라도 알려야 한다 |
| **판정 대상과 현재 상태가 어긋난 것** | 납품 mp3는 옛 필터인데 코드는 새 필터다. G2를 이 mp3로 하시면 어긋난 것을 판정하시는 셈 |
| **누적된 신호** | 문서 실측 기록이 세 번째로 재현 안 됨 → 개별 오타가 아니라 계통 문제 |
| **막힌 것** | ffmpeg 미설치로 mp3 재생성·`review-video` 전체가 막혀 있다 |

**나쁜 소식을 묻지 않는다.** 일정이 늘었으면 늘었다고 먼저 쓴다. 이 프로젝트는 "틀렸으면 인정하고 원문을 남긴다"가 규칙이다.

### 3. 미결 · 이월

표로. **무엇이 왜 안 끝났는지**까지. 다음 날 이 표가 그대로 출발점이 된다.

### 4. 다음 작업

**하나만 고른다.** 우선순위 목록이 아니라 "다음에 이걸 한다"를 쓰고, 왜 그것이 먼저인지 한두 문장 붙인다.

### 5. 검수 요청

검수자가 **답을 줘야 진행되는 것**만. 없으면 "없음"이라고 쓰고, 다음 검수 지점이 언제인지 적는다.

## 지킬 것

**세션로그와 같은 사실을 두 번 쓰지 않는다.** `CLAUDE.md` 2절이 경고하는 그대로다 — 같은 사실이 두 곳에 있으면 반드시 어긋난다. 데일리보고는 **요약이 아니라 선별**이다. 실측표 전체를 옮기지 말고 판단에 필요한 값 하나만 남기고 링크한다.

**검수자 시점으로 쓴다.** "내가 무엇을 했는가"가 아니라 "당신이 무엇을 알아야 하는가"다.

## 하지 말 것

- 세션로그 실측표 통째로 복사
- 반성·소회 (바이브로그로)
- "잘 진행됨" 같은 내용 없는 문장
- 프로젝트 버전 매기기 · `백업/` 스냅샷에 넣기 — 일일 마감 문서는 프로젝트 버전 체계 밖이다
