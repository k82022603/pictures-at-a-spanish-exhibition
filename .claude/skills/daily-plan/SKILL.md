# 일일 계획

**하루의 시작이다.** `daily-closing`이 저녁에 하는 일을 아침에 거꾸로 한다 — 마감이 "무엇을 했나"라면 계획은 "무엇을 할 것이고 왜 오늘인가"다.

산출물은 하나. `98. 일일 마감/YYYYMMDD-0-daily-plan.md`

| 파일 | 주기 | 재호출 시 |
|---|---|---|
| `YYYYMMDD-0-daily-plan.md` | 하루 1개 | **갱신하지 않는다** — 아래 "계획은 틀려도 고치지 않는다" 참조 |

파일명 앞자리가 `-0-`인 이유는 정렬이다. 하이픈(0x2D)이 어떤 숫자보다 앞서므로 하루 폴더가 정확히 시간순으로 늘어선다.

```
20260807-0-daily-plan.md        ← 계획   (아침, 하루 1개)
20260807-0930-session-log.md    ← 사실   (수시)
20260807-1737-session-log.md
20260807-daily-report.md        ← 판단   (저녁, 하루 1개)
20260807-vibe-log.md            ← 회고   (저녁, 하루 1개)
```

---

## 0. 날짜를 실제로 확인한다

기억이나 추측으로 쓰지 않는다. `daily-closing`과 같은 규칙이다.

```bash
date "+%Y%m%d %H%M"
```

---

## 1. 어제를 읽는다 — 세 곳에서, 이 순서로

계획을 `CLAUDE.md` 7절만 보고 세우면 **어제 발견한 함정을 놓친다.** 명세는 결론만 갖고 있고, 함정은 일지에 있다.

```bash
ls "98. 일일 마감/" | tail -8
```

| 읽을 곳 | 무엇을 얻는가 |
|---|---|
| 어제 **데일리보고 3절 미결·이월** · **4절 다음 작업** | 오늘 후보의 뼈대. 4절은 이미 하나로 좁혀져 있다 |
| 어제 **바이브로그 "내일 집중할 것"** · "아직 모르는 것" | 검수자가 아니라 **작업자가 자기에게 남긴** 우선순위 |
| 어제 **마지막 세션로그 "이어서 할 때 알아야 할 것"** | **함정이 여기 있다.** 작업본과 납품물의 어긋남, 재현 안 되는 값, 설치 안 된 도구 |

세 곳이 어긋나면 세션로그가 정본이다 — 가장 사실에 가깝다.

---

## 2. 착수 가능한 것만 고른다

하고 싶은 것과 **오늘 실제로 할 수 있는 것**은 다르다. 두 가지를 대조한다.

- `CLAUDE.md` 7절 — 착수 대기 표의 우선순위
- `01. 작업 분해 구조와 백로그.md` — WBS 선행 관계

**운영 규칙: 게이트 우선 — 승인 전에 다음 Phase를 착수하지 않는다**(`01` 문서). 선행이 미충족인 항목을 오늘 일에 넣으려면, **왜 넣는지와 어디서 멈출지**를 계획에 적어야 한다. 예: "G2 승인 대기 중이지만 되돌릴 범위가 여기서 끊기므로 여기까지만".

**하루에 본체는 하나다.** 나머지는 그 본체의 렌더 대기 시간에 끼워 넣는 곁가지다. 본체가 둘이면 둘 다 반쯤 된다.

---

## 3. 블록으로 쪼갠다

표 하나로 하루 전체를 보여주고, 블록마다 서술형으로 **왜 오늘인지**를 쓴다(R6).

| # | 블록 | 예상 | 산출 |
|---|---|---|---|

각 블록에 들어갈 것:

- **왜 오늘인가** — 순서에 이유가 없으면 순서가 아니다. "A가 B의 선행이라서", "렌더 대기 중에 끼워서", "1.4 착수 직전이라 지금 아니면 오판해서"
- **무엇으로 끝났다고 판정하는가** — 산출물 또는 통과할 숫자
- **막히면 어디로 가는가** — 대안 경로가 있으면 미리

긴 렌더가 있으면 **시간을 알려주고 시작한다**(`CLAUDE.md` 8절). 계획 단계에서 렌더 예상 시간을 적어두면 곁가지를 어디에 끼울지가 정해진다.

---

## 4. "오늘 하지 않는 것"을 반드시 쓴다

**하지 않기로 한 것도 판단이다.** 이 절이 없으면 저녁에 "왜 저건 안 했지"를 복원할 수 없고, 다음날 같은 것을 또 후보로 올린다.

적을 것:
- 우선순위에서 밀린 백로그와 **밀린 이유**
- 지금 하면 **이중 작업**이 되는 것 (나중 단계에서 어차피 다시 만질 것)
- 게이트에 막힌 것
- 프로젝트 금지 사항 중 오늘 유혹이 될 만한 것 (`CLAUDE.md` 9절)

---

## 5. 계획은 명세를 복사하지 않고 가리킨다

`CLAUDE.md` 2절이 못박은 것 — **"같은 사실이 두 곳에 있으면 반드시 어긋난다."** 일일 문서도 예외가 아니다.

| 쓰지 말 것 | 대신 |
|---|---|
| 회귀 기준값을 표로 베껴 쓰기 | "회귀 기준값은 `05` 9.10절이 정본" |
| WBS 소요일·임계경로 숫자 | "`01` WBS 1.4 표 참조" |
| 악장 사양 전문 | "`07` 4장 6악장 절" |

계획에 쓰는 것은 **오늘 하기로 한 것과 그 이유**다. 숫자는 링크한다.

---

## 6. 계획은 틀려도 고치지 않는다

**중요하다.** 하루가 끝난 뒤 계획을 결과에 맞춰 손보면 **그 순간 회고 재료가 사라진다.**

아침에 세운 것이 저녁에 틀렸다면 틀린 채로 둔다. 그 차이를 다루는 것은 계획이 아니라 데일리보고 3절(미결·이월)과 바이브로그다. R3(문서 내용 삭제 금지)를 하루 단위로 적용한 것이다.

같은 날 "계획 다시 세워줘"를 들으면 — 기존 파일을 고치지 말고 **본문 끝에 `## 개정 (HH:MM)` 절을 덧붙여** 무엇이 왜 바뀌었는지 적는다. 프로젝트 문서의 개정 절과 같은 방식이다.

## 7. 마무리 확인

- [ ] `date` 로 확인한 실제 날짜를 썼다
- [ ] 파일명이 `YYYYMMDD-0-daily-plan.md` 다. 언더바 없음
- [ ] 어제 **세션로그의 "이어서 할 때 알아야 할 것"**을 실제로 읽었다
- [ ] 오늘의 **본체가 하나**로 정해졌다
- [ ] 각 블록에 **왜 오늘인지**가 있다
- [ ] **"오늘 하지 않는 것"** 절이 있다
- [ ] 명세의 숫자를 베끼지 않고 절 번호로 가리켰다
- [ ] 선행 미충족인 것을 넣었다면 **어디서 멈출지**를 적었다
- [ ] 답변 끝에 `작성 일자: YYYY-MM-DD`

## 이 폴더는 프로젝트 버전 체계 밖이다

`daily-closing`과 같다. 계획 문서는 **명세가 아니라 일지**다.

| | 프로젝트 문서 (`00`~`08`) | 일일 계획 · 마감 |
|---|---|---|
| 버전 | 전체 하나 (v1.12 등) | **없음** |
| 스냅샷 | `백업/vN.N .../` | **안 넣는다** |
| `검증.py` | 검사 대상 | 루트 `*.md`만 훑으므로 **안 잡힌다** |
| 고칠 때 | `doc-revise` 절차 | 그냥 쓴다 (단, 계획은 6절대로 개정 절) |

계획을 세우다 **프로젝트 문서를 고쳐야겠다고 판단되면 그건 오늘의 블록으로 넣고**, 실제 수정은 `doc-revise` 절차를 밟는다. 계획 세우는 김에 슬쩍 고치지 않는다.
