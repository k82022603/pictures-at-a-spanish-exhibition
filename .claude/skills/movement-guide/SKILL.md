# 전곡 음원 안내표

**9분 40초를 통으로 주면 어디를 들어야 할지 알 수 없다.**

검수자 지시로 생긴 규칙이다 (2026-08-11).

> **"다음부터 전악장 음원 파일 만들고 나서는 표 형식으로 악장별 구간 및 해설하는 것 잊지 말아주고."**

---

## 0. 언제 쓰는가

**전곡 파일을 하나라도 새로 만들면 쓴다.** 요청을 기다리지 않는다.

| 상황 | 붙이는가 |
|---|---|
| 전곡 mp3 를 새로 인코딩했다 | **예** |
| 같은 렌더를 파일 이름만 바꿔 다시 구웠다 | **예** — 검수자는 그 파일을 처음 듣는다 |
| 발췌만 냈다 | 아니오. 그때는 **R7 네 칸 표**(`CLAUDE.md` 8절) |
| 숫자만 보고했다 | 아니오 |

**R7 네 칸 표와 다른 것이다.** 발췌는 「이 20초에서 무엇이 다른가」를 말하고, 이 표는 「9분 40초 중 어디로 가야 하는가」를 말한다. **전곡을 낼 때는 둘 다 필요할 수 있다.**

---

## 1. 손으로 적지 않는다

```bash
python "99. 작업 스크립트/악장표.py"
```

**구간·빠르기·음량·편성을 코드와 음원에서 생성한다.** 손으로 옮겨 적으면 어긋난다 — 이 프로젝트에서 문서와 코드가 어긋난 사고가 여러 번 있었고(`97. 회고` T-02), 그래서 이 도구가 생겼다.

빠르기를 **♩ / ♪ / ♩. 로 구분해 찍는다.** 단위를 헷갈리면 악보가 두 배 빨라 보인다.

---

## 2. 표 — 일곱 칸

| 악장 | 구간 | 길이 | 빠르기 | 음량 | 무슨 일이 일어나는가 | **집중해서 들을 지점** |
|---|---|---|---|---|---|---|

### 칸마다 지킬 것

| 칸 | 규칙 |
|---|---|
| **구간** | **`분:초`로 적는다.** `160초`는 플레이어에서 못 찾는다. `2:40` 은 찾는다 |
| 길이 | 초로. 「이 악장이 얼마나 이어지는가」의 감각이다 |
| **빠르기** | 숫자와 **풀어쓴 판을 나란히** — `♩=100 · 행진 속도`. 단계로 바뀌면 `76→84→96 단계`로 |
| **음량** | dB 와 **역할**을 함께 — `−22.8 · 곡의 바닥`, `−15.8 · 정점`. 숫자만 쓰면 안 읽힌다 |
| 무슨 일이 | 그 악장의 **존재 이유** 한 줄. 설계 정본은 `CLAUDE.md` 6절 악장 표와 `07` |
| **집중해서 들을 지점** | **가장 중요한 칸. 반드시 시각을 박는다** — `4:26~4:35 발소리만 남는 구간`. **악장 전체를 가리키면 안 붙인 것과 같다.** 쓰는 법은 아래 2.1 |

### 2.1 「귀에 무엇이 들어오는가」로 쓴다 (2026-08-12 신설)

**형식은 `CLAUDE.md` 8절이 정본이다.** 여기에는 **확인 목록**만 둔다.

- [ ] **소리의 모양**을 적었다 — 악기 이름이 아니라 (`또르르 흐른다` · `뚝 끊긴다` · `깔린다`)
- [ ] **시각을 전부** 적었다 — 「N마디마다」가 아니라 `5:25 · 5:33 · 5:41 …`
- [ ] **그 시각을 음원에서 쟀다** — 마디 길이를 곱해서 적지 않았다
- [ ] **얼마나 오래**인지 적었다 (`3.7초 노래하고 4.3초 쉰다`)
- [ ] **크기를 일상의 것**에 견줬다 (`라디오를 살짝 줄이는 정도`)
- [ ] **몇 초만 들으면 되는지** 적었다 (`5:25부터 12초`)
- [ ] A/B 면 **A 에서는 무엇이 다른지** 적었다

> **기계 설명 금지** — `0.56배로 감쇠` · `vel 0.44 → 0.62` · `−5 dB`. **그건 내가 한 일이지 들리는 소리가 아니다.**

### 그리고

- **그날 바뀐 악장에 표시(★)를 하고, 안 바뀐 악장은 「다시 들으실 필요 없다」고 명시한다.** 검수자의 시간이 가장 비싸다
- **판정이 필요한 것과 그냥 흐르는 것을 구분한다.** 전부 굵게 하면 아무것도 안 굵다
- 표 끝에 **한 문장으로 무엇을 정해주셔야 하는지** 적는다 (`CLAUDE.md` 8절)

---

## 3. 숫자는 가리키고 베끼지 않는다

**실측 정본은 `05` 9장의 가장 나중 절이다.** 표에 쓰는 dB·빠르기는 `악장표.py` 가 그 렌더에서 뽑은 값이므로 그대로 쓰되, **회귀 기준값이나 통과 조건은 이 표에 적지 않는다.**

스킬이 정본의 수치를 사본으로 들면 정본이 바뀔 때 반드시 어긋난다(BL-26). 오늘의 실측을 적는 것과 기준값을 복사하는 것은 다르다.

---

## 4. 파일 이름도 함께 본다

전곡 파일을 낼 때 **이름이 내용과 맞는지** 확인한다.

- **「승인판」은 검수자가 승인한 것에만 쓴다.** 승인 뒤에 내가 손댄 것은 「수정판(미승인)」이다
- **승인받은 파일은 내용도 이름도 바꾸지 않는다.** 새 판은 반드시 새 파일이다
- 기준선으로 쓸 파일은 **sha256 을 문서에 박는다** — 이름은 바뀌어도 해시는 안 바뀐다

`97. 회고` **T-11** 이 이 셋이 왜 생겼는지다.

## 마무리 확인

- [ ] `악장표.py` 를 실제로 돌렸다 (손으로 안 적었다)
- [ ] 구간이 **분:초**다
- [ ] 「집중해서 들을 지점」에 **시각이 박혀 있다** — 열 악장 전부
- [ ] 바뀐 악장에 ★, 안 바뀐 악장은 안 들어도 된다고 적었다
- [ ] 빠르기·음량에 **풀어쓴 판**이 붙어 있다
- [ ] 파일 이름이 내용과 맞는다
- [ ] 무엇을 정해주셔야 하는지 한 문장으로 끝맺었다
- [ ] 답변 끝에 `작성 일자: YYYY-MM-DD`

## 하지 말 것

- 전곡 파일을 내고 **표 없이 보내기**
- 구간을 **초 단위 숫자**로 적기
- 「집중해서 들을 지점」에 **"전체적으로 들어보세요"** 라고 쓰기
- `악장표.py` 안 돌리고 기억으로 적기
- 정본의 **기준값을 이 표에 베끼기**
