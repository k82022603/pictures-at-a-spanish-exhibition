# T-08. 파일을 비운 뒤에 예외가 났다

**2026-08-08 · v2.9 드럼 편성 문서화 중 · 프로젝트 v2.9**

---

## 증상

`01. 작업 분해 구조와 백로그.md` 가 **0바이트**가 됐다. 44,799바이트짜리 문서였다.

바로 눈치채지 못했다. 스크립트가 예외를 던졌길래 "치환 문자열이 안 맞았구나" 하고 다시 grep 했는데 **BL-31 이 안 나왔다.** 그때도 인코딩 문제인 줄 알았다. 파일 크기를 재고서야 알았다.

---

## 원인 — 파이썬의 평가 순서

```python
io.open(f, 'w').write(fn(t))
```

파이썬은 **`io.open(f,'w')` 를 먼저 평가한다.** 그 순간 파일이 비워진다. 그다음에 인자 `fn(t)` 를 계산하는데, 거기서 예외가 나면 **`write` 는 아예 호출되지 않는다.**

빈 파일만 남는다.

---

## 원인은 하나다 — 확인하지 않았다

`open(f, 'w')` 는 여는 순간 파일을 비운다. **파이썬을 쓰는 사람이면 아는 것이고 나도 몰랐던 게 아니다. 그냥 보지 않았다.**

### 처음 쓴 반성문은 이 자리에 다른 것을 적었다 (v2.9, 원문 보존)

처음에는 이렇게 썼다.

> 오늘 하루 멀쩡히 쓰던 두 줄짜리 헬퍼를 **토큰을 아끼려고** 한 줄로 압축했다. 두 줄 판은 "계산을 끝내고 연다"는 안전성을 갖고 있었는데 어디에도 적혀 있지 않아서 조용히 사라졌다. (…) 아끼려던 "세션 한도"는 5시간마다 리셋되는 창이었다 — 아낄 필요가 없었다.

검수자가 **"핑계도 많다"**고 했고, 맞다.

세션 한도도, 두 줄이 한 줄이 된 것도, 안전성에 이름이 없던 것도 **전부 정황이다.** 압축하지 않고도 같은 코드를 쓸 수 있었고, 두 줄로 썼어도 순서를 안 봤으면 똑같이 났다. **원인 자리에 정황을 놓으면 그 자체가 변명이다.**

> **"왜 그랬나"를 쓸 때, 나를 덜 나쁘게 만드는 설명이 먼저 떠오르면 그건 원인이 아니다.**

### 그러면 "어제는 왜 못 봤나"의 답은

**이 사건에는 그 절이 성립하지 않는다.** 다른 회고들은 "그 조건에서는 보이지 않았다"가 있었다 — T-06 은 지표 해상도 아래였고, T-01 은 악장 하나만 고쳐봐야 드러났다.

**여기는 보였다.** 코드 한 줄을 읽으면 되는 것이었다.

이 폴더의 규칙 2 가 "부주의로 결론내지 않는다"인데, **부주의가 진짜 원인인 경우도 있다.** 그때 억지로 구조적 설명을 만들면 규칙이 변명 생성기가 된다.

## 무엇이 살렸나 — 오늘 아침에 붙인 git

```bash
git checkout HEAD -- "01. 작업 분해 구조와 백로그.md"
```

한 줄로 44,799바이트가 돌아왔다.

**어제였으면 이게 없었다.** `백업/v2.8` 스냅샷으로 돌아가야 했고, 그건 v2.9 작업분을 잃는다는 뜻이다. 더 나빴을 수도 있다 — **오전에 만든 v2.4~v2.8 을 하루 안에 다섯 번 스냅샷했기 때문에 운이 좋았던 것이지, 스냅샷 주기가 길었으면 그만큼 잃는다.**

> **git 을 도입한 날 그 git 이 값을 했다.** 하루도 안 걸렸다.

`96. 운영` 가이드 2장이 "코드 이력이 없으면 G2 승인 음원을 다시 못 만든다"고 적었는데, 그건 **먼 위험**처럼 보였다. 오늘 드러난 것은 **가까운 위험**이다 — 이력은 몇 달 뒤가 아니라 **십 분 뒤**에 쓰인다.

## 고침

헬퍼에 **이름을 붙였다.** 구조만 되돌리지 않고 왜 그런지 적었다.

```python
def rw(f, fn):
    """**결과를 먼저 계산하고 그다음에 연다.**
    io.open(f,'w') 는 여는 순간 파일을 비운다. fn 이 예외를 던지면
    빈 파일만 남는다 — 2026-08-08 에 01 문서를 이렇게 날렸다(git 으로 복구)."""
    raw = io.open(f, encoding='utf-8', newline='').read()
    nl = '\r\n' if '\r\n' in raw else '\n'
    out = fn(raw.replace('\r\n', '\n')).replace('\n', nl)   # 먼저 계산
    io.open(f, 'w', encoding='utf-8', newline='').write(out)  # 그다음 쓴다
```

---

## 고치지 못한 것 — 여러 파일 편집이 원자적이지 않다

그 스크립트는 `07` 을 먼저 고치고 `01` 에서 죽었다. **`07` 에는 v2.9 내용이 들어갔고 `01` 은 비었다.** 절반만 적용된 상태로 남는다.

이번에는 git 이 있어서 되돌렸지만, **구조적으로는 그대로다.** 여러 문서를 한 스크립트로 고치는 한 언제든 다시 난다.

막을 방법은 있다 — 전부 계산한 뒤 마지막에 한꺼번에 쓰는 것이다.

```python
결과 = {f: 계산(f) for f in 대상}   # 하나라도 실패하면 여기서 멈춘다
for f, out in 결과.items(): 쓴다   # 여기서는 실패할 일이 없다
```

**지금은 안 했다.** 하는 편이 낫지만, 오늘 이미 사고가 났으므로 **또 고치다 또 날리는 것**을 피한다. 다음에 문서 편집 스크립트를 쓸 때 이 형태로 한다.

**절차로만 막은 것을 적어둔다** — T-03 에서 배운 대로다. 절차는 잊힌다.
