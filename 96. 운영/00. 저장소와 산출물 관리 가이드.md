**2026-08-08 신설.** 문서·코드는 GitHub이, 음원·영상은 Google Drive가 갖는다.

이 폴더는 **프로젝트 버전 체계 밖**이다. `97. 회고`·`98. 일일 마감`과 같다 — 명세가 아니라 **도구 사용법**이고, 도구는 음악 설계와 다른 속도로 바뀐다. 버전 없음, `백업/` 스냅샷에 안 넣음, `검증.py`가 안 봄.

## 1. 왜 갈랐나 — 이 절만 읽어도 나머지가 따라온다

**git은 한 번 넣은 파일을 영원히 기억한다.** 나중에 지워도 이력에 남아 저장소 크기가 줄지 않는다. 이 프로젝트는 하루에 mp3를 두세 개씩 만들므로, 그것을 커밋하면 **한 달에 0.7 GB씩** 붇는다. 검토 영상 한 편은 114.6 MB로 **GitHub의 파일 한도 100 MB를 아예 넘는다.**

Git LFS는 무료 할당이 월 1 GB라 이 속도를 감당하지 못한다.

그래서 이렇게 갈랐다.

| | 어디에 | 왜 |
|---|---|---|
| 문서 · 코드 · 스킬 | **GitHub** | 텍스트라 가볍고, **차이를 볼 수 있다** |
| 음원 · 영상 | **Google Drive** | 무겁고 diff가 무의미하다 |
| 원본 사진 · 참고 악보 | **로컬만** | 저작권 · 개인 기록 |
| 렌더 wav · 스템 1.4 GB | **로컬만** | 코드를 돌리면 다시 생긴다 |

> **"무엇이 있었는가"는 GitHub이 알고, "그 파일"은 Drive에 있다.**

`산출물/<날짜>/README.md`가 그 연결점이다. **README는 git이 정본이고, 같은 파일이 Drive에도 복사된다** — Drive만 열어도 그 음원이 무엇인지 알 수 있어야 하기 때문이다. 고칠 때는 git 쪽만 고친다.

## 2. 왜 코드 이력이 이 프로젝트에서 특별히 중요한가

렌더는 **비트 단위로 재현된다.** 같은 코드를 두 번 돌리면 100.0000% 같은 wav가 나온다(BL-30, 2026-08-07). 그래서 음원은 원리적으로 **"다시 만들 수 있는 것"**이다.

**단, 코드가 남아 있을 때만 그렇다.**

2026-08-08까지 이 프로젝트에는 git이 없었고 `백업/`은 마크다운만 담았다. `CLAUDE.md`는 *"스킬은 백업에 안 넣는다 — git이 이력을 갖는다"*고 적어뒀는데 **그 git이 없었다.** 결과적으로 **G2 승인 음원을 만든 코드가 어디에도 없다.**

| 음원 | 다시 만들 수 있나 |
|---|---|
| G2 승인 판정 대상 (2026-08-07) | **못 만든다** |

**2026-08-08이 경계선이다.** 그 이전 산출물은 Drive에 올려두는 것이 유일한 보존이고, 각 날짜 README 머리에 그렇게 적혀 있다.

### 코드가 있어도 반드시 보관하는 것 둘

### 커밋 전 확인 — 공개 저장소다

새 종류의 파일을 넣기 전에 훑는다.

```bash
git diff --cached --name-only | grep -Ei "\.(mp3|mp4|wav|mov)$"
git grep -lI "k82022603@gmail" HEAD
git grep -lIiE "(ghp_|github_pat_|api[_-]?key|secret|password)" HEAD
```

셋 다 결과가 없어야 한다. **git이 한글 경로를 이스케이프해서 출력하므로** `core.quotepath false`가 설정돼 있어야 위 grep이 동작한다(이미 설정됨).

### 흔한 함정

- **한글 경로 이스케이프** — 위와 같다. `git config core.quotepath false`
- **CRLF 경고** — `.gitattributes`가 `* text=auto`로 정규화한다. 경고는 무시해도 된다
- **100 MB 한도** — 넘으면 푸시 자체가 거부된다. 영상은 Drive로

### 푸시가 멈추면 — 자격증명 관리자다

**증상** — `git push` 가 아무 출력 없이 몇 분씩 매달린다. `git ls-remote` 는 잘 되는데 푸시만 안 된다.

**원인** — Windows 기본 자격증명 관리자(Git Credential Manager)가 **보이지 않는 대화형 창**을 띄우고 기다린다. Claude 의 셸은 비대화형이라 그 창에 답할 수 없고, 그래서 영원히 멈춘다.

```bash
tasklist | grep -i credential      # git-credential-manager.exe 가 떠 있으면 이것이다
```

**고침 — `gh` 로 넘긴다.** `gh` 는 이미 인증돼 있고(키링) 대화형 창을 띄우지 않는다.

```bash
git config --local credential."https://github.com".helper "!gh auth git-credential"
taskkill //F //IM git-credential-manager.exe      # 매달린 것을 치운다
git push origin main
```

2026-08-08 에 이것으로 세 번 막혔다. **`git ls-remote` 가 되는데 푸시가 안 되면 네트워크가 아니라 자격증명이다.**

#### 왜 MCP 로는 음원을 못 올리나

**권한 문제가 아니라 통로의 문제다.** 연결이 살아 있어도 이 길로는 안 된다.

#### README 는 MCP 로도 되는데 왜 rclone 으로 올리나

된다. 그래도 안 쓰는 이유가 둘이다.

1. **MCP 에는 덮어쓰기가 없다.** 만들기만 되므로 마감마다 올리면 **같은 이름의 README 가 계속 쌓인다.** `rclone copy` 는 바뀐 것만 제자리에서 갱신한다
2. **경로가 둘이면 어긋난다.** README 는 MCP 가 사흘 전에 올린 것, 음원은 rclone 이 오늘 올린 것 — 이런 상태가 생긴다. **한 명령으로 폴더 통째를 맞추는 편이 낫다**

음원 때문에 rclone 은 어차피 필요하므로 README 만 따로 뗄 이유가 없다.

#### MCP 가 실제로 한 일

2026-08-08 에 Drive 프로젝트 폴더와 날짜 폴더 넷을 **MCP 로 만들었다.** 폴더 ID 를 그 자리에서 돌려주므로 README 의 링크에 바로 넣을 수 있었다.

앞으로 새 날짜 폴더도 이쪽이 편하다 — **다만 rclone 이 없는 폴더는 알아서 만들므로, 링크를 미리 알아야 할 때만 MCP 를 쓴다.**

### 설정 — 열쇠는 프로젝트 폴더 안에 둔다

`.rclone.conf` (프로젝트 루트, **`.gitignore` 대상**)

```ini
[drive]
type = drive
scope = drive
root_folder_id = 1VKkKWI5kTLqeCjlnBL5GTZsc6JbDQHmu
token = ...          <- rclone 이 쓴다. 사람이 손대지 않는다
```

**`root_folder_id` 덕에 경로가 짧아진다.** `drive:20260808 - 0악장 첫 기둥` 처럼 날짜 폴더 이름만 쓰면 된다.

#### 왜 윈도우 설정 폴더가 아니라 여기인가

**Claude 의 도구는 프로젝트 폴더 밖에서 검수자와 다른 파일을 본다.** 2026-08-08 에 윈도우 설정 폴더 아래에 설정을 만들었더니, Claude 쪽에서는 625바이트 파일이 보이는데 검수자의 PowerShell 에서는 `not found` 였다. **샌드박스를 꺼도 같았다.**

프로젝트 폴더 안은 둘이 같은 것을 본다 — git·문서·코드가 전부 정상 동작하는 것이 증거다. 그래서 여기 둔다. **그러면 Claude 가 업로드를 직접 실행할 수 있다.**

대가는 **토큰이 작업 폴더에 놓인다**는 것이다. 그래서 `.gitignore` 가 세 겹으로 막고(`.rclone.conf` · `*.rclone.conf` · `rclone.conf`), 업로드 스크립트가 **실행 때마다 차단 여부를 확인**하고 안 걸리면 중단한다.

> **"Claude 가 못 한다"고 단정하기 전에 다른 실행 경로를 확인한다.**
> 그날 Bash 로만 시도하고 안 된다고 보고했다. 검수자가 *"스크립트 만들어놓으면 되잖아"* 라고 짚었고, 프로젝트 폴더 안이라는 통로가 남아 있었다.

#### 만들기 — 검수자가 한 번 (브라우저 인증)

```powershell
rclone config create drive drive scope=drive root_folder_id=1VKkKWI5kTLqeCjlnBL5GTZsc6JbDQHmu --config "<프로젝트 폴더>\.rclone.conf" | Out-Null
```

브라우저가 열리고 승인하면 끝이다. 그 뒤로는 **Claude 가 스크립트로 올린다.** 열쇠가 없으면 업로드 스크립트가 이 명령을 완성된 형태로 찍어준다.

#### `| Out-Null` 이 붙은 이유 — 2026-08-08 에 토큰이 새어 나갔다

**`rclone config create` 는 끝나면 완성된 설정을 화면에 통째로 찍는다. `refresh_token` 까지 포함해서다.** 그날 그 출력을 대화에 붙여넣으면서 토큰이 노출됐고, Google 계정 권한을 폐기하고 다시 발급했다.

rclone 은 **안내 메시지(인증 URL·진행 상황)를 stderr 로, 완성된 설정을 stdout 으로** 내보낸다. 그래서 stdout 만 버리면 인증 과정은 그대로 보이면서 토큰만 안 보인다.

> **인증 명령을 안내할 때는 무엇이 화면에 찍히는지부터 확인한다.**
> `gh auth login` 은 토큰을 안 찍고 `rclone config create` 는 찍는다. 같은 종류의 명령이라고 같게 동작하지 않는다.

**토큰이 노출됐다면** — <https://myaccount.google.com/permissions> 에서 rclone 액세스 권한 삭제 → `.rclone.conf` 삭제 → 위 명령으로 재발급. `access_token` 은 한 시간 뒤 만료되지만 **`refresh_token` 은 수명이 길다.**

#### `scope=drive` 에 대해

Drive **전체** 읽기·쓰기 권한이다. `drive.file`(rclone 이 만든 파일만)로 좁히면 더 안전하지만, **날짜 폴더를 rclone 이 아니라 다른 도구가 만들었으므로** 그 폴더에 못 들어간다. 좁히려면 폴더 구조를 rclone 으로 다시 만들어야 한다.

### 올리기 — 스크립트 하나다

```bash
bash "99. 작업 스크립트/드라이브 업로드.sh" --dry     # 무엇이 올라갈지만 본다
bash "99. 작업 스크립트/드라이브 업로드.sh"           # 올린다
```

무엇이 올라가는지 목록을 찍고, `copy` 한 뒤, Drive 현황을 다시 찍는다.

- `copy`는 **없는 것만** 올린다. `sync`는 Drive 쪽에만 있는 파일을 **지우므로 쓰지 않는다**
- **`README.md`도 함께 올린다.** Drive만 열었을 때 그 음원들이 무엇인지 알아야 한다 — 설명 없는 mp3 열 개는 쓸모가 없다. 정본은 git이고 **Drive 쪽은 읽기 전용 사본**이다. `copy`가 한 방향이라 마감 때마다 자동으로 갱신된다. **Drive의 README를 손으로 고치지 않는다** — 고치면 다음 마감에 덮인다
- 매번 **`.rclone.conf`가 `.gitignore`에 걸리는지 확인**하고 안 걸리면 중단한다

## 5. 하루 흐름에서 이것이 어디 끼는가

```
아침   daily-plan
낮     작업 → 음원이 나오면 산출물/<날짜>/ 에 넣고 README 에 한 줄
저녁   daily-closing  ─┬─ 세션로그 · 데일리보고 · 바이브로그 · 작곡일지
                       ├─ 산출물 README 빠진 곳 채우기
                       ├─ rclone copy  (Drive 업로드)
                       └─ git commit + push
```

**파일을 만드는 그 자리에서 README에 한 줄 적는다.** 마감 때만 쓰기로 하면, 마감이 안 온 날(R8 — 마감은 검수자가 말했을 때만 돈다)의 파일이 정체 불명으로 남는다.

## 6. `산출물/` 규약

```
산출물/YYYYMMDD - 그날의 한 마디/README.md
```

폴더 이름은 `98. 일일 마감/`과 같은 **R2 예외**다. 근거도 같다 — **날짜 정렬이 곧 시간 순서.** 뒤에 한 마디를 붙이는 것은 날짜만으로는 무엇을 한 날인지 알 수 없기 때문이다.

**버전이 아니라 날짜로 가르는 이유** — 하루에 프로젝트 버전이 열둘 오른 날이 있다(2026-08-07). 검수자가 기억하는 단위는 버전이 아니라 **"그날 무엇을 들었는가"**다.

README 표는 네 칸이다.

| 칸 | 무엇 |
|---|---|
| 파일 | 이름 그대로 |
| 무엇 | 한 줄. **무엇을 판정하려고 만들었나** |
| 검수 | ★ 채택 / 미채택 / 실패 / 기준선 / — |
| (본문) | 왜 그 파일이 그렇게 생겼는지. **실측 숫자는 `05`를 가리키고 복사하지 않는다** |

**미채택된 것도 지우지 않는다.** "무엇과 비교해서 저것을 골랐는가"가 판정의 절반이다. 오늘 0악장 A판이 그 예다.

## 7. 되돌리기

| 상황 | 방법 |
|---|---|
| 커밋을 잘못했다 (푸시 전) | `git reset --soft HEAD~1` |
| 푸시한 것을 되돌린다 | `git revert <sha>` — **`reset --hard` + 강제 푸시는 쓰지 않는다** |
| 큰 파일을 실수로 커밋했다 | **이력에서 지우려면 저장소를 다시 쓰는 수밖에 없다.** 그래서 3절의 커밋 전 확인이 있다 |
| Drive에서 잘못 지웠다 | Drive 휴지통 30일 |
| 문서를 되돌린다 | `백업/vN.N .../` 를 꺼낸다. **되돌린 것도 앞으로 흐르는 새 버전으로 기록한다**(`04` 5장) |
