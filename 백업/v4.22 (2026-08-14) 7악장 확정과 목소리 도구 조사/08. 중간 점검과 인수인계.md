## 1. 무엇이 만들어졌나

하루 만에 v0.1에서 v1.7까지 왔다. 집계는 이렇다.

| 구분 | 수량 |
|---|---|
| 문서 | 9개 (`00`~`08` + `CLAUDE.md`) · 약 10.2만 자 |
| 파이썬 스크립트 | 20개 · 3,793줄 |
| 스킬 | 4개 |
| 버전 스냅샷 | 10개 (v0.2 ~ v1.6) |
| 산출 음원 | 7개 (30초 데모 → 전곡 9분 40초) |
| 산출 영상 | 3개 (ELP풍 30초 → 화성 검토 영상 9분 40초) |

**가장 중요한 산출물 둘.**

| 파일 | 무엇 |
|---|---|
| `전곡 코드 진행 v1.4 - 성부 진행 최적화 9분40초.mp3` | 320 kbps · 44.1 kHz. ~~**음질 판정의 기준**~~ |
| `전곡 코드 진행 v1.4 - 화성 검토 영상.mp4` | 1080p30 · H.264 High. 유튜브 업로드용 |

> **⚠ 「음질 판정의 기준」이 틀렸다 (2026-08-12).** MP3 는 **소리를 실제로 버린다** — 재보니 −56.5 dB 이고 **하필 9악장 정점에서 가장 많이 버린다**(신호 대 오차 34.7 dB). **압축해서 버린 파일을 음질 기준으로 삼고 있었다.** 2026-08-12 부터 **32비트 FLAC 이 납품 정본**이고 MP3 는 호환성용이다. 경위는 [10. 렌더와 음원 파일](<10. 렌더와 음원 파일 — 소리가 만들어져 파일이 되기까지.md>).

그리고 **문서가 아닌 자산**이 하나 더 있다 — 자체 합성 악기다. 피아노(가산합성 + 현 비조화도), 현악(8성부 디튠), 나일론 기타·리켄배커 베이스(Karplus-Strong), 해먼드(9드로바 + 레슬리), 무그(라더 필터), 팔마스·카혼·타콘. **샘플을 하나도 쓰지 않았으므로 권리가 전부 이 프로젝트에 있다.** [06 문서](<06. 음악 제작 방식 결정서.md>) 4.4절의 판정 근거 중 하나가 이것이었다.

## 3. 판단이 바뀐 다섯 번

이 프로젝트의 규칙 R3(기존 내용을 삭제하지 않는다)이 있어서 되짚을 수 있다. **바뀐 이력 자체가 이 프로젝트의 자산이다.**

### (1) 없던 인물을 넣지 않는다 → 넣되 만드는 과정을 보여준다

`02` 문서 초안은 "없던 인물 추가는 개인 기록의 진실성을 훼손한다"고 못박았다. 서사가 도입되며 뒤집혔는데, **원문을 남겨 뒀더니 뒤집힌 게 아니라 범주가 확장된 것임이 드러났다.** 그녀가 2005년에 있었다고 주장하지 않고, 2026년의 화자가 사진에 누군가를 들여놓는 장면을 보여주면 위조가 아니라 고백이 된다.

`02` 문서 7.4절에 남아 있다.

### (2) E 프리지안 → D 프리지안

주제 B의 조성이다. E 프리지안은 C장조와 음이 같아서 B♭장조와 두 음이 다르다. **D 프리지안은 B♭장조의 상대 선법**이라 같은 일곱 음을 쓴다. "두 주제는 같은 선율이다"라는 명제가 비유가 아니라 음악적 사실이 됐고, "반음 하나"의 정체도 F♯으로 확정됐다.

### (3) 가안 주제 → MusicXML 원본 채보

내가 만든 가안 주제는 11박이었고 마디에 딱 맞았다. 그래서 늘어졌다. 원곡을 채보해 보니 **프레이즈가 9박이고 마디가 11박**이었다. 그 어긋남이 이 곡의 엔진이다.

검수자가 "템포 너무 느림"이라고 했을 때 나는 BPM을 올릴 생각을 했다. 원인은 템포가 아니었다.

### (4) E♭ 장조 → E♭ 리디안 (6악장)

`07 작곡 계획`은 론다를 E♭장조로 설계했는데, E♭장조에는 A♭이 있고 그건 이 곡의 음집합 밖이다. 크로마 실측에서 6악장 A♭ 비중이 0.097로 **조성 밖 음 1위**로 나왔다.

E♭ 리디안은 `E♭ F G A B♭ C D` — B♭장조와 완전히 같은 일곱 음이다. 음집합을 지키면서 곡에서 가장 독특한 색을 얻었다. **이 개정에서 가장 마음에 드는 발견이다.**

### (5) 순차 작곡 → 세 기둥 먼저 (승인 대기)

WBS는 1악장부터 순서대로 쓰게 되어 있었다. `07` 문서에서 **0·4·9악장을 먼저 세우고 도시 악장, 마지막에 연결 프롬나드**로 바꾸자고 제안했다. 전환은 양쪽 강변을 알아야 다리를 놓을 수 있고, 모든 것이 피날레를 향해야 한다.

아직 승인되지 않았다.

## 4. 검수 지적이 프로젝트를 밀고 왔다

여섯 번의 지적이 있었고, 여섯 번 다 방향을 바꿨다. 기록해 둔다.

| # | 지적 | 결과 |
|---|---|---|
| 1 | "건반이 위주야 베이스가 위주야?" | 3성부 분리 원칙. 온셋 상관 실측으로 검증 |
| 2 | "오아시스가 아니었음. **Renaissance 〈Mother Russia〉**" | 참조 기준 전면 교체. ELP는 변주 원천으로 격하 |
| 3 | "혼자가 아닌 누군가와 함께 하는 이야기" | 서사 도입. 그녀(La Duende) 신설, `03` 문서 |
| 4 | "**르네상스는 건반이나 보컬이 훌륭하지만, 중심은 베이스임**" | 리켄배커 물리 모델 + "베이스는 걷는 몸" 설계 |
| 5 | "조잡하다? 1970년대 수준 미디" | BL-06 판정, 테이프 새추레이션, 경직됨 1.185 → 0.941 |
| 6 | "1970년대 신디사이저를 좋아하는 것이 **조잡한 소리도 수용한다는 뜻이 아님**" | 마스터 체인의 +6 dB 프레즌스 부스트 폐기 |

**4번과 6번은 내가 스스로 도달할 수 없었던 지적이다.**

4번은 장르에 대한 판단이었다. 나는 "베이스는 독립 대선율"이라고 문서에 써놓고 실제로는 근음을 조금 피한 저음 반주를 만들고 있었다. 악기를 바꾸는 것으로는 절반만 해결됐고, 나머지 절반인 **역할**은 서사에서 찾아야 했다.

6번은 한 문장이 판정 하나를 통째로 뒤집은 경우다. "1970년대 소리를 좋아한다"는 정보만 있었을 때 나는 그것을 "덜 다듬어진 소리를 수용한다"로 읽었다. 실제로는 **"그 시대의 질감은 좋지만 합성의 조악함은 다르다"**는 뜻이었고, 그 구분이 마스터 체인의 프레즌스 부스트를 찾아내게 했다.

## 6. 소회

세 가지가 남는다.

### 제약이 컨셉이 된 것이 네 번

| 제약 | 컨셉 |
|---|---|
| 사진이 저해상도다 | **"상상 속 인물에게는 얼굴이 없다"** |
| 합성 현악이 앞에 못 나선다 | 6악장 **"비움으로 만드는 광활함"** |
| 사람 목소리가 없다 | **"언어 없는 목소리에는 신디사이저가 맞다"** |
| 음집합을 지켜야 한다 | 6악장 **E♭ 리디안** |

네 번 다 처음에는 "무엇을 포기할까"로 시작했다가 **"이 제약이 원래 그래야 했던 것은 아닐까"**로 물음을 바꾸면서 풀렸다. 얼굴 없는 실루엣은 서사적 정당성·해상도 한계·AI 얼굴 왜곡을 한꺼번에 해결했다. 그건 타협이 아니라 더 나은 답이었다.

이 프로젝트에서 이 방법이 네 번 통했다는 사실이 우연 같지 않다.

### 숫자가 두 번 나를 잡았다

**1악장의 F♯**과 **6악장의 A♭**. 둘 다 문서에는 "F♯이 유일한 조성 밖 음"이라고 적혀 있는데 음원에는 그렇지 않았다. 귀로만 판단했다면 **중심 명제가 거짓인 곡**을 만들어 놓고 몰랐을 것이다.

크로마 검사가 없었으면 못 잡았다. 그래서 이 프로젝트의 "귀가 아니라 숫자로 먼저 검증한다"는 원칙은 취향이 아니라 필요다.

### 내가 반복한 실수 — 다음 세션이 경계할 것

**문서에 주장을 써놓고 코드로 구현하지 않는 것.** 같은 실수를 세 번 했다.

- "베이스는 독립 대선율" — 써놓고 저음 반주를 만들었다
- "F♯이 유일한 조성 밖 음" — 써놓고 `G7`·`A7♭9`·`Ddim7`을 넣었다
- "6악장은 광활한 현악" — 써놓고 낼 수 없는 소리였다

전부 **문서가 코드보다 앞서 나간** 경우다. `검증.py`와 `검증화성.py`가 존재하는 이유가 이것이고, 스킬 `harmony-verify`에 "모든 악장에서 조성 밖 음 1위가 F♯이어야 한다"를 못박아 둔 것도 이것 때문이다.

새 세션은 **문서의 주장을 사실로 믿지 말고 측정할 것.**

### 문서 규칙이 오늘의 인수인계를 싸게 만들었다

R3(삭제 금지)와 버전 스냅샷은 검수자가 정한 규칙이다. 처음에는 작업 비용이었다. 그런데 오늘 Cowork에서 Claude Code로 넘기면서, **대화 맥락이 하나도 넘어가지 않는데도 인수인계가 거의 공짜였다.** `00`~`07` 문서와 `04` 개정 이력이 이미 인수인계 문서였기 때문이다.

기록을 남기는 규칙이 도구를 바꿀 자유를 만들었다.

## 7. 실무 팁 — Claude Code로 넘어가며

### 어디서 열 것인가 — Desktop의 "Code" 탭을 권한다

터미널 CLI와 Claude Desktop의 "Code" 탭은 **같은 도구다.** 공식 문서에 "각 표면은 동일한 Claude Code 엔진에 연결되므로 CLAUDE.md·설정·MCP 서버가 모든 표면에서 그대로 동작한다"고 되어 있다. `CLAUDE.md`와 `.claude/skills/`는 어느 쪽에서 열든 똑같이 읽힌다.

Desktop을 권하는 이유는 셋이다.

| 이유 | 설명 |
|---|---|
| **인라인 diff** | 이 프로젝트의 제1 규칙이 "삭제 금지"다. 무엇이 지워졌는지 **눈으로 바로 확인**할 수 있다 |
| **세션 병렬** | 전곡 렌더가 몇 분 걸린다. 한쪽에서 렌더하고 다른 쪽에서 문서 작업 |
| 설치할 게 없다 | 이미 Claude Desktop을 쓰고 있다 |

되돌릴 수 없는 선택이 아니다. `/desktop`으로 터미널 세션을 데스크톱으로 넘기고, `claude --teleport`로 가져올 수 있다.

### Windows에서 먼저 확인할 세 가지

```bash
python -c "import numpy, scipy, PIL; print('ok')"
ffmpeg -version
bash --version
```

**`bash --version`이 중요하다.** Windows에서 Git for Windows가 없으면 Claude Code는 PowerShell을 셸로 쓰는데, `.claude/skills/`의 명령 예시가 전부 POSIX 셸 기준이라 그대로 동작하지 않는다. 막히면 [Git for Windows](https://git-scm.com/downloads/win)를 설치하면 된다.

### 스킬을 쓰게 만들 것

`.claude/skills/`에 네 개가 있다. **작업을 시작할 때 해당 스킬을 읽었는지 확인하는 습관**을 들이면 좋다. 안 읽으면 절차를 매번 다시 추론하고, 그러다 한 단계씩 빠뜨린다.

| 스킬 | 언제 |
|---|---|
| `doc-revise` | 문서를 고칠 때 |
| `harmony-verify` | 렌더·검증할 때 |
| `compose-movement` | 악장을 작곡·수정할 때 |
| `review-video` | 유튜브 검토 영상을 만들 때 |

의심스러우면 그냥 **"스킬 읽고 시작해줘"**라고 하면 된다.

### 긴 작업은 시간을 먼저 물을 것

전곡 렌더가 2코어에서 4~5분이었다. PC에서는 줄겠지만 여전히 몇 분이다. **"이거 얼마나 걸려?"를 먼저 물으면** 기다릴지 다른 걸 할지 정할 수 있다.

### git을 병행할 만하다

`백업/` 스냅샷 10개는 "v1.6끼리 맞는 세트"를 보장하는 역할이라 그대로 두는 게 맞다. 다만 git을 함께 쓰면 **문서 간 diff를 보는 게 훨씬 편해진다.** `.gitignore`는 만들어 뒀다 — 사진 99MB와 영상 120MB가 제외된다.

```bash
git init
git add .
git commit -m "v1.6 — 전곡 화성 진행과 유튜브 검토 영상"
```

### 되돌리는 법을 알아둘 것

무언가 잘못됐다고 느끼면 스냅샷에서 통째로 되돌릴 수 있다.

```bash
cp "백업/v1.5 (2026-08-05) 전곡 화성 진행/"*.md .
python "99. 작업 스크립트/검증.py"
```

되돌린 것도 **앞으로 흐르는 새 버전**으로 기록한다. v1.7에서 v1.5로 갔으면 그것은 v1.8이다.

## 9. G2.5 직전 자체 평가 (v2.8, 2026-08-08)

세 기둥(0·4·9)이 다 선 시점이다. 검수자가 전곡을 듣고 **"자체 완성도를 평가해달라"**고 해서 적는다. 이 장은 **상태 기록**이지 사건 기록이 아니다 — 사건은 `97. 회고`가, 하루는 `98. 일일 마감`이 갖는다.

### 9.1 먼저 — 내가 판정할 수 없는 것

**나는 이 음원을 듣지 못한다.** 숫자와 구조만 본다. 그래서 "좋은가"에는 답할 수 없고 **"설계대로 되어 있는가"와 "무엇이 아직 없는가"**만 말할 수 있다.

겸양이 아니라 한계다. **v1.3이 "조잡하다" 판정을 받았을 때도 숫자로는 통과였다.** 그때 경직됨 지표가 1.185였다는 것은 나중에 그 지표를 만들고 나서야 알았고, 지적이 먼저였다.

### 9.2 완성도의 실체 — 곡의 65%는 아직 스케치다

| | 시간 | 비중 |
|---|---|---|
| 세 기둥 (0·4·9) — WBS 1.4 작곡 완료 | 205초 | **35%** |
| **아직 v1.4 스케치** | **375초** | **65%** |

스케치로 남은 것 — 1 마드리드 40초 · 2 변주I 15초 · 3 세고비아 55초 · 5 변주II 15초 · 6 론다 50초 · **7 그라나다 100초** · **8 바르셀로나 100초**.

**7·8악장이 둘이서 곡의 34%다.** 오늘 4·9악장에 들어간 종류의 작업(컴파스 겹침·벨팅·악장별 잔향)이 아직 안 들어갔다.

> **전곡 음원이 있다는 것과 전곡이 완성됐다는 것은 다르다.** 지금 들리는 것은 **골격이 선 스케치**다.

### 9.3 숫자로 확실한 것 — 화성은 튼튼하다

| | 값 |
|---|---|
| 외성 병행 5도·8도 | 화음 349개에 **0건 / 0건** |
| 7반음 초과 도약 | **0건** |
| 조성 밖 음 | F♯ 하나. 나머지는 측정 바닥(0.045 이하) |
| 렌더 재현성 | **비트 단위.** 하루를 건너뛰어도 100.0000% |

**음집합 하나로 10악장을 쓴다는 중심 아이디어가 무너지지 않았다.** 이 곡에서 가장 확실한 부분이다. 3장이 기록한 "판단이 바뀐 다섯 번" 중 셋이 이 원칙을 지키려다 나온 것이고, 그 대가가 지금 여기 있다.

### 9.4 걱정하는 것 넷

**① 경직됨 0.948인데 승인받은 건반 스케치는 0.916이었다.** v1.3의 1.185보다는 훨씬 낫지만 **아직 그 스케치에 못 미친다.** 오늘 잔향이 0.955 → 0.948로 내렸는데, 남은 0.032가 편곡으로 좁혀질지 합성기의 한계인지 **모른다.**

**② 드럼이 없다.** *(v2.9 — 검수자가 "드럼 잡자"로 답했고 편성이 확정됐다. 그 자리에서 **내가 낸 편성안이 틀렸다**는 것도 드러났다 — `07` 15장. 아래 원문은 남긴다.)* WBS 1.1.6(드럼 패턴 재설계)이 미완이고 지금 편성에 드럼 키트가 아예 없다 — 4악장의 카혼·팔마스뿐이다. "화성이 들리는 최소 구성"이라는 이유로 미뤄왔으나, **프로그레시브 록에서 리듬 섹션의 절반이 비어 있다.** 8악장 7/8이 드럼 없이 "가장 격렬"해지기는 어렵다.

> **이것은 편곡이 아니라 편성 결정이다.** 나중에 넣으면 전 악장의 균형이 다시 움직인다 — 오늘 잔향에서 겪은 것과 같은 종류이고, BL-29·BL-30을 1.4 착수 전에 끝낸 이유와도 같다. **늦을수록 비싸진다.**

**③ 현악이 피아노 대비 −18 dB다** (BL-23). "공기"라는 역할 규정으로 정당화했지만 **심포닉이라 부르기엔 얇다.** 6악장은 그 제약을 "비움으로 만드는 광활함"으로 바꿔 성공했는데(5장의 방법 그대로), **나머지 악장도 그런지는 확인되지 않았다.**

**④ 보컬이 없다.** 노랫말은 확정됐고(`07` 11장) 자리도 잡혔지만(0악장 38.5초) 소리가 없다. BL-28 미착수다. **0악장의 그 자리는 지금 빈 채로 들린다.**

### 9.5 오늘 드러난 구조적 약점

**세 기둥 셋 중 둘에서 "문서에 적고 코드에 없는 것"이 나왔다.** 6악장(`05` 9.11절)과 9악장(`05` 9.16절)이다. 6장이 이미 이름 붙인 실수이고, 착수 실사가 없었으면 둘 다 못 봤다.

> **나머지 다섯 악장에도 같은 것이 있을 확률이 높다고 본다.**

이건 완성도의 문제가 아니라 **내가 아직 모르는 미완성이 얼마나 되는지 모른다**는 뜻이다. 5장 "남은 위험"에 이 항목을 더해야 한다.

### 9.6 그래서 G2.5에서 볼 것

**숫자로는 전부 통과다. 그런데 오늘 통과한 숫자들이 "조잡하다"를 못 걸렀던 그 숫자들과 같은 종류다.**

`07` 7장이 정한 판정 기준 둘 — **4악장 베이스 부재가 느껴지는가 · 9악장에서 두 주제가 하나였다는 게 느껴지는가.** 나머지 65%는 이 골격 위에 쌓으므로, 골격이 틀렸다면 지금 고치는 것이 다섯 악장을 쓴 뒤보다 훨씬 싸다.

**함께 여쭐 것이 드럼 부재다**(9.4 ②). 편성 결정이라 미룰수록 비싸진다.

## 10. 이 방식은 통상의 작곡과 무엇이 같고 다른가 (v3.9, 2026-08-10)

검수자 질문에서 나온 장이다.

> **"이런 방식으로 다른 작곡가들도 작업한다는 것이지?"**

**절반만 그렇다.** 그리고 다른 절반이 이 프로젝트의 성격과 약점을 동시에 설명한다.

### 10.1 같은 것 — 재료는 정석이다

**선율 하나를 변형해 이야기를 나르는 방식은 오래된 정석이다.**

| 어법 | 어디서 |
|---|---|
| **라이트모티프** — 인물·사물에 선율을 붙이고 상황에 따라 변형 | 바그너 이후 오페라 전반 |
| **고정악상(idée fixe)** — 한 선율이 악장마다 모습을 바꾸며 돌아온다 | 베를리오즈 《환상 교향곡》 |
| 주제 변형으로 서사를 진행 | **영화음악 대부분** |
| 콘셉트 앨범 — 앨범 하나가 하나의 이야기 | **프로그레시브 록.** 검수자 기준인 Renaissance가 그 계열 |

**주제 A와 B가 같은 선율의 두 모습**인 것, 악장마다 상태가 달라지는 것(씨앗 → 출현 → 겹침 → 협화 → 단독 → 파편 → 해소)은 **전부 이 계보 안에 있다.**

**음집합 하나로 곡 전체를 묶는 것**도 20세기 이후 흔한 방법이다. 이 곡은 `B♭ C D E♭ F G A` 일곱 음만 쓰고 중심음만 바꾼다.

> **재료와 어법은 새롭지 않다. 새로울 필요도 없다.**

### 10.2 다른 것 — 만드는 순서가 거꾸로다

**서사를 문서로 먼저 확정하고, 표로 관리하고, 숫자로 검증하는 것은 작곡가의 방식이 아니라 이 프로젝트의 방식이다.**

| | 통상 | 이 프로젝트 |
|---|---|---|
| 시작 | **악기 앞에서 친다** | **문서에 서사를 쓴다** |
| 설명 | 나중에 붙거나 안 붙는다 | **먼저 있다** |
| 판정 | 귀 | **숫자 먼저, 귀 나중** |
| 이력 | 악보와 기억 | **문서·git·스냅샷** |

이 순서에는 이유가 있다. **작곡자가 대화 사이에 기억을 잃는다.** 세션이 끊기면 어제의 판단이 남지 않으므로, 판단을 문서 밖에 둘 수 없다. `CLAUDE.md`가 그래서 존재한다.

### 10.3 대가 — 소리를 가장 늦게 만난다

**2026-08-10에 그 대가를 정확히 치렀다** (`97. 회고` T-09).

9악장 종결의 F♯→F를 이렇게 만들었다.

```
03 문서 5장 "상실이 아니라 편입"  →  07 문서 14장 "버티다가 놓는 소리"  →  코드
```

**세 단계를 내려오는 동안 한 번도 소리로 확인하지 않았다.** 숫자는 전부 통과했다. 검수자가 듣고 3초 만에 판정했다 — **"우스꽝스러움."**

원인은 **넓은 비브라토 → 하강 포르타멘토 → 비브라토 소멸**의 순서가 서양 대중음악에서 **낙담·실패의 관용구**라는 것이었다. 만화의 「뿌우—」다.

> **피아노 앞에서 만들었으면 불가능한 실수다.** 손으로 치는 순간 웃긴 것을 안다.

**문서에서 코드로 내려오는 방식은 이력이 남는 대신 소리를 마지막에 만난다.** 그리고 그 사이에 **의도한 의미가 들리는 의미를 가린다** — `glide`에 "내려앉는다"는 이름을 붙이면 그 이름으로 듣게 된다.

### 10.4 숫자 검증은 그 대가를 다 못 막는다

숫자 검증(`검증화성.py`)은 이 대가를 줄이려고 넣은 장치이고 실제로 여러 번 값을 했다 — 경직됨 1.185 → 0.941, 병행 5도 0건, 조성 밖 음.

**그러나 숫자는 「우스꽝스러운가」를 못 잰다.** 잴 수 있는 것과 없는 것의 경계가 여기다.

| 숫자가 잡는 것 | 못 잡는 것 |
|---|---|
| 음이 맞는가 | **무슨 이야기로 들리는가** |
| 성부가 매끄러운가 | 관용구를 밟았는가 |
| 밀도·음량 설계대로인가 | 지루한가 |

`CLAUDE.md` 8절은 **"음악은 귀가 아니라 숫자로 먼저 검증한다"**고 적었다. **「먼저」라고 적혀 있지 「숫자로만」이 아니다.** T-09에서 그것을 「만」으로 읽었다.

### 10.5 그래서 하나를 절차에 넣는다

**악장을 만들면 그 악장이 어떤 이야기로 들리는지 사람에게 물어본다.**

숫자 통과는 **필요조건이지 충분조건이 아니다.** 그리고 이 검사는 3초면 끝난다 — 오늘 3초에 나왔다.

**통상의 작곡가는 이 검사를 자기 손으로 계속 하고 있다.** 우리는 그것을 절차로 복원해야 한다.

### 10.6 그리고 검수자가 준 더 큰 판정

> **"멜로디, 선율만 가지고 나를 이해시킨다는 것은 불가능. 가사가 함께 있어야 함."**

**10.3의 대가와는 다른 층의 문제다.** 9:26을 고쳐도 남는다.

곡의 중심 아이디어(반음 하나가 「함께」)가 **선율만으로는 도달하지 않는다**는 판정이고, 이것은 라이트모티프 계보 전체가 안고 있는 한계이기도 하다 — **바그너의 라이트모티프도 가사와 무대가 함께 있을 때 작동한다.** 순수 기악에서 서사를 읽어내는 것은 훈련된 청자의 일이다.

**노랫말(BL-28)의 우선순위가 「도시 악장 뒤」에서 앞으로 온다.** 상세는 `07` 11장 개정 절.

> **이 프로젝트는 뮤직비디오다. 영상이 서사의 절반을 지도록 설계돼 있다.** 다만 지금은 음악만 있는 상태이고, **음악만으로 판정받는 동안은 음악이 혼자 이야기해야 한다.**

## 11. 너무 무난한 곡을 만들고 있는가 (v4.2, 2026-08-10)

검수자 질문이다.

> **"듣기에 너무 무난한 (너무 대중적인) 곡을 만들고 있는 것이 아닌지 평가해주세요."**

**답은 예다.** 다만 무난한 곳이 예상과 다르다.

### 11.1 재본 것 — 화성 어휘가 좁다

| | |
|---|---|
| 서로 다른 화음 | **22종** (341개 중) |
| 상위 넷 | **51%** — E♭maj7(20%) · Gm7 · Cm7 · Dm |
| **긴장 화음** | **7%** (24개) |
| 순수 3화음 | 37% |

**maj7·m7이 곡을 지배한다.** 서양 음악에서 가장 편안한 색이고 재즈 발라드·뉴에이지가 쓰는 화음이다.

**음량은 문제가 아니었다** — 1초 단위 5~95% 폭이 10.3 dB, 3 dB 넘게 튀는 곳이 69군데다.

### 11.2 그런데 진짜 문제는 재료가 아니라 손질이다

**2026-08-10 하루에 한 변경 다섯을 나열하면 이렇다.**

| 무엇 | 방향 |
|---|---|
| 템포 단계화 | 급변 대신 **계단** |
| 9:26 미끄러짐 제거 | **거슬리는 것 제거** |
| 6악장 협화 추가 | **부드럽게** |
| 무음 구멍 메우기 | **끊김 제거** |
| 8악장 리프 척추 | **빈 곳 채우기** |

**다섯 전부 마찰을 줄이는 쪽이다. 늘린 것이 하나도 없다.**

각각은 정당했다 — 구멍은 구멍이고 관용구는 관용구다. **문제는 반대 방향으로 미는 힘이 이 프로젝트에 하나도 없다는 것이다.**

### 11.3 최적화해 온 숫자의 이름이 「경직됨」이다

**1.185 → 0.926.** 낮을수록 좋다고 정해놓고 아홉 달을 끌고 왔다. **이름 자체가 방향이다.**

> **「덜 거칠게」를 재는 숫자는 있는데 「더 흥미롭게」를 재는 숫자가 하나도 없다.**

10장이 적은 것의 연장이다 — **숫자로 판정하는 방식의 대가는 잴 수 있는 것만 좋아진다는 것**이다.

### 11.4 통과 기준이 18세기 것이다

**병행 5도 0건 · 도약 0건.** 음악원 화성학 시험 채점 기준이고, 나는 그것을 통과 조건으로 걸고 매번 자랑스럽게 보고했다.

**프로그레시브 록의 성격은 그 규칙을 어기는 데서 나온다.**

그리고 **4악장에서는 그 규칙이 명백히 틀렸다.** 플라멩코 기타의 라스게아도는 **병행 화음으로 움직이는 것이 어법**이다. `voice_lead()`의 병행 벌점(40.0)이 그 악장을 **스페인 음악이 아니게** 만들고 있다.

> **제약을 컨셉으로 바꾼다**(5장)를 아홉 번 성공했는데, **컨셉을 제약으로 되돌린 자리**가 여기다.

### 11.5 폐기한 화음이 전부 날카로운 것들이었다

`G7` · `A7♭9` · `Ddim7` · `A♭maj7`. **음집합을 지키려는 이유는 정당했지만, 결과적으로 이를 드러낼 수 있는 화음을 전부 없앴다.**

**복권하지 않는다.** 음집합이 이 곡의 중심 아이디어다. **날카로움은 화음이 아니라 어법·음량·박자에서 가져온다** — BL-34가 그 목록이다.

### 11.6 안 무난한 것들 (버리면 안 된다)

- **9박 프레이즈와 11박 마디의 어긋남** — 곡의 엔진이고 진짜 안 대중적이다
- **7/8 (2+2+3)**
- **4악장에 드럼이 없고 베이스가 멈춘다**
- **6악장 ♩=56에 마디당 두세 음**
- **9분 40초, 후렴 없음**

> **재료는 안 대중적인데 손질이 대중적이다.**

### 11.7 인정할 편향

**나는 「매끄럽다」를 「좋다」로 읽는다.**

검수자가 2026-08-10 하루에 그것을 두 번 교정했다 — *"전반적으로 곡이 심심합니다"*, 그리고 이 질문.

> **내가 스스로 "이건 너무 안전한데"라고 말한 적이 하루 종일 한 번도 없다.**

숫자는 그것을 못 잡는다. **T-09가 세운 절차 1번(사람에게 물어본다)이 여기에도 그대로 적용된다** — 다만 물을 것이 "무슨 이야기로 들리는가"가 아니라 **"이거 너무 안전하지 않은가"**다.

**다음 작업은 `01` BL-34다.**

### 11.8 개정 — 다섯을 하고 나서 (v4.4, 2026-08-11)

**BL-34 다섯을 하루에 다 했다.** 그리고 이 장의 주장 하나가 실측으로 증명됐고, 하나는 수정이 필요하다.

**증명된 것 — 11.3절.** 병행을 74번 넣고, 비명을 셋에서 넷으로 키우고, 음량 폭을 1 dB 벌리고, 마디 격자를 세웠는데 **경직됨은 0.926 → 0.929 로 0.003 움직였다.** 「덜 거칠게」를 재는 숫자는 오늘 한 일을 거의 못 본다. **잴 수 있는 것만 좋아진다**는 말의 뒷면이 이것이다 — **못 재는 것은 좋아져도 모른다.**

**수정할 것 — 11.4절이 「통과 기준을 풀면 된다」고 읽히게 쓰여 있었다.** 실제로는 아니었다.

> **금지를 없앤다고 그 자리에 무엇이 들어오지는 않는다.**
> 병행 벌점을 0 으로 준 결과는 **병행 5도 0건**이었다. 평행을 **보상**해야 평행이 나왔고, 그것도 윗 성부만이어야 화음의 정체가 안 깨졌으며, **화성 바닥을 내려야** 미끄러질 자리가 생겼다.

**「제약을 컨셉으로 바꾼다」의 반대는 「제약을 없앤다」가 아니다.** 없앤 자리에 무엇을 놓을지가 진짜 작업이고, 오늘 ① 에 쓴 시간의 대부분이 그것이었다.

**그리고 하나 더 — 오늘 다섯 중 셋에서 「내가 적어둔 사실」이 틀렸다.**

| 무엇 | 적혀 있던 것 | 실제 |
|---|---|---|
| ② 비명 | "곡에서 **한 번** 쓴다" | **세 번** — 호출 자리가 하나였을 뿐 |
| ⑤ 엔진 | "9박 대 11박을 **더** 드러낸다" | **열 악장 중 0악장에만 있다** |
| ① 수락 조건 | "병행 건수가 0 이면 실패" | **74번 미끄러져도 그 지표는 0** |

**셋 다 세어 보지 않고 적은 것이다.** 그리고 셋 다 **코드를 읽으면 5분 안에 알 수 있는 것**이었다. 11.7절이 「나는 매끄러움을 좋음으로 읽는다」를 인정했는데, 오늘 것은 그것과 다른 결함이다 — **취향이 아니라 확인의 문제**다.

## 12. 프로그레시브 록의 매력과 이 곡 (v4.13, 2026-08-12)

**검수자 지시다.**

> **"프로그레시브락의 매력이 무엇인지 다시 한번 더 탐구하도록."**

11장이 「너무 무난한가」에 **예**라고 답한 것의 다음 걸음이다. 그때 마지막 문장이 *"다음 작업은 `01` BL-34다"*였고, 그 다섯은 승인·구현됐다. **이 장은 그 뒤에 무엇이 남았는지를 잰다.**

### 12.1 이 장이 나온 경위 — 내가 반대 방향으로 가고 있었다

**오늘 아침 계획의 본체는 「프롬나드 네 악장의 화성 보이싱 상한을 65로 낮춰 목소리 자리를 비운다」였다.** 검수자가 그 자리에서 뒤집었다.

> **"반주 화음과 목소리 겹치는 구간 허용함. 전적으로 허용함. 사람 목소리도 악기라고 생각하고 다른 악기들과 어우려지면 됨."**

**내가 깔고 있던 전제는 「목소리가 주인공이고 나머지는 비켜서야 한다」였고 그것은 대중가요의 관습이다.** 프로그레시브 록에서 목소리는 **층 안에 있다.** 층이 겹쳐 있는 것 자체가 그 음악의 재미인데 **나는 그것을 결함으로 읽고 걷어내려 했다.**

**그리고 방향이 또 「빼는 쪽」이었다.** 하필 곡에서 가장 두꺼워야 할 9악장에서 화음 공간 7칸을 빼려 했다. 11.2절에 *"다섯 전부 마찰을 줄이는 쪽이다. 늘린 것이 하나도 없다"*고 적고 사흘 만이다.

> **11.7절이 인정한 편향이 고쳐지지 않았다** — 「나는 매끄럽다를 좋다로 읽는다」. 인정하는 것과 안 하는 것은 다르다.

### 12.2 무엇을 재기로 했나 — 「좋다」로 끝내지 않는다

11.3절이 남긴 문제가 이 장의 출발점이다.

> **「덜 거칠게」를 재는 숫자는 있는데 「더 흥미롭게」를 재는 숫자가 하나도 없다.**

그래서 **매력을 항목으로 쪼개고 항목마다 「이 곡에서 어디를 보면 되는가」를 붙였다.** 붙지 않는 항목은 잰 것이 아니므로 버렸다.

**저작권 선을 지켰다**(`CLAUDE.md` 6절) — 창법·음역·음색은 참조하고 **편곡·가사·구성은 안 본다.**

### 12.3 새 도구 — `주역교대.py`

**`악장표.py`는 악장 전체의 평균으로 「주인공」을 하나 찍는다. 그래서 악장 안에서 주역이 바뀌는지는 안 보인다.** 8악장은 4마디마다 주역이 바뀌게 설계했는데(`07` 18장) 그 표에는 「주인공: 피아노, 베이스」로만 나온다.

**프로그레시브 록에서 성부가 대등하다는 것은 평균이 고르다는 뜻이 아니라 시간에 따라 앞에 나오는 악기가 바뀐다는 뜻이다.** 그래서 시간축으로 썰었다 — 2초 창, 창마다 1등을 찾고, 1등이 바뀐 횟수를 센다.

**스템에 페이더를 곱해서 읽는다.** 곱하기 전 값으로 재면 해먼드가 거의 모든 악장의 주인공으로 나온다(`05` 9.21절이 같은 함정에 빠졌던 자리다).

> 그 둘이 무엇인가 — **4악장은 「밀도를 무에서 쌓아 올린다」로 설계했고 8악장은 「4마디마다 주역이 바뀐다」로 설계했다.** 즉 **의도적으로 설계한 두 악장에서만 일어난다.** 나머지 여덟은 「화성을 깔고 주제를 얹는」 같은 구조다 — 11장을 쓰게 만든 지적(*"열 악장이 하는 일이 같았다"*)이 **아직 여덟 악장에 남아 있다.**

>
> **G2.5 판정이 「선율만으로는 이해 불가」였다.** 가사가 필요하다는 판단은 검수자 것이고 그대로 유지된다. 다만 **주제 B가 한 번도 앞에 안 나온다면 이해가 안 되는 이유가 하나 더 있는 것이다.** 이 둘은 서로 배타적이지 않다.

**③ 앞줄이 얇다.** 성부 8개 중 평균 **2.3개**만 1등에서 6 dB 안에 있다. **6악장 1.5개가 최저인데 그건 설계다**(「비움으로 만드는 광활함」). 문제는 **0악장 1.6 · 5악장 1.7 · 1악장 1.9** — 프롬나드와 마드리드가 6악장만큼 얇다. **비어 있어야 할 악장과 그렇지 않은 악장이 같은 두께다.**

**④ 악장 안에서 갑자기 터지는 자리가 4악장 말고 없다.** 이웃한 2초 창 사이의 가장 큰 도약이 **4악장 24.7 dB · 6악장 7.3 · 0악장 5.5이고 나머지 일곱은 1.4~4.7 dB**다. **악장 경계에서만 극적이고 악장 안에서는 완만하다.** BL-33이 템포에서 고친 것과 **같은 모양의 문제가 음량에 남아 있다.**

### 12.6 이 측정이 못 보는 것

**에너지(RMS)는 주목을 못 잰다.** 무그가 −20 dB이고 피아노가 −16 dB이어도, **음색이 또렷하고 음역이 겹치지 않으면 사람은 무그를 「선율」로 듣는다.** 그러므로 ②를 **「그녀가 안 들린다」로 읽으면 안 되고 「에너지로는 한 번도 앞에 안 선다」로 읽어야 한다.**

**판정은 귀가 한다.** 다만 **설계가 「그녀의 목소리」라고 못박은 악장에서 반주가 4 dB 크다는 사실**은 그 자체로 물어볼 값이다.

### 12.7 그리고 이 장도 「없다」를 두 번 확인했다

11.8절이 남긴 것 — *"셋 다 세어 보지 않고 적은 것이다."*

이번에는 **세고 나서 적었다.** 다만 **아직 못 센 것이 있다.**

- **주제가 동시에 몇 개 울리는가** — 스템으로는 안 갈린다. 주제 A와 B가 같은 성부에 실려 있다
- **다시 들으면 다른 것이 들리는가** — 잴 방법이 없다. **못 잰다고 적는다**
