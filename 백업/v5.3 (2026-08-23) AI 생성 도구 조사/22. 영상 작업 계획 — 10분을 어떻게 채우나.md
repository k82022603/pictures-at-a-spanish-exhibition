## 3. 도시별 밀도가 7배 벌어진다

### 3.1 왜 이렇게 됐나

**사진은 여행에서 찍힌 대로이고, 악장 길이는 음악이 정한 것**이다. 둘이 맞을 이유가 없다.

| 도시 | 사진 | 악장 길이 | 「적정 3~4초」로 채우려면 |
|---|---|---|---|
| 마드리드 | **8장** | 58.0초 | **15~19장 필요** — 7~11장 모자라다 |
| 세고비아 | 25장 | 29.1초 | 7~10장이면 된다 — **15장 남는다** |
| 세비야 | 26장 | 96.1초 | 24~32장 — **거의 맞는다** |
| 론다 | 26장 | 34.3초 | 9~11장 — 15장 남는다 |
| 그라나다 | 75장 | 117.9초 | 29~39장 — **36장 남는다** |
| 바르셀로나 | **84장** | 82.0초 | 21~27장 — **57장 남는다** |

**마드리드만 모자라고 나머지는 다 남는다.** 특히 **바르셀로나는 3분의 1만 쓰면 된다.**

### 3.2 쓸 수 있는 수 넷

| 수 | 무엇 | 어디에 |
|---|---|---|
| **멀티패널** | **세로 사진 두세 장을 한 화면에 나란히.** `00` 기획서가 이미 설계해 둔 것 | **바르셀로나(세로 49장) · 그라나다(세로 35장)** |
| **셀렉** | A/B/C 등급을 매겨 A 만 쓴다 | 남는 도시 전부 |
| **한 장을 두 번** | 다른 자리를 잘라 쓰면 다른 그림이 된다 | **마드리드** |
| **프롬나드로 넘기기** | 남는 사진을 프롬나드 악장에 | 아래 4장 |

**세로 사진 107장을 두 장씩 묶으면 화면 수가 54개로 준다.** 그만큼 시간이 벌린다.

## 4. 프롬나드 202초가 비어 있다

**0 · 2 · 5 · 9 악장을 합치면 202.4초 — 전체의 33%다.** 여기에 무엇을 놓을지 정해진 것이 없다.

| 악장 | 길이 | 서사에서 무엇인가 |
|---|---|---|
| **0** Promenade 제시 | 70.5초 | 주제와 걸음을 심는다. **여행이 시작되기 전** |
| **2** 변주 I | 27.0초 | 두 번째 발소리 |
| **5** 변주 II | 35.0초 | 두 주제 첫 겹침 |
| **9** The Great Gate | 69.9초 | 두 주제 총주. **결론** |

**프롬나드는 「걷는 악장」이다.** 도시와 도시 사이이고, 여행자가 **이동 중**이다.

### 4.1 후보 넷 — 아직 정하지 않았다

| 후보 | 무엇 | 걸리는 것 |
|---|---|---|
| **길·이동 사진** | 기차 창밖, 거리, 골목 | **그런 사진이 몇 장인지 안 세어 봤다** |
| **도시 사진 중 남는 것** | 바르셀로나 57장이 남는다 | **도시가 섞이면 「어디를 걷는지」가 흐려진다** |
| **타이포그래피** | 악장 이름·도시 이름·날짜 | `00` 기획서에 타이포 항목이 있다(WBS 3.5) |
| **그녀(La Duende)** | 실루엣이 지나간다 | **G3 PoC 통과가 선행** |

**9악장은 특히 중요하다** — **결론이고 두 주제가 총주로 겹치는 자리**다. 여기에 무엇을 놓느냐가 **이 작품이 무엇을 말하는지**를 정한다.

## 5. 도구 — 무엇으로 만드나

### 5.1 Remotion — 오늘 확인했다

**코드로 영상을 만든다.** *"3분 04초에 이 사진을 넣고 5초 동안 천천히 확대한다"* 를 글로 적으면 영상이 나온다.

| 확인한 것 | 결과 |
|---|---|
| 이 PC 에서 도는가 | **된다** — Node v22.14 · Remotion 4.0.515 |
| 켄번스(사진에 천천히 줌·팬) | **된다.** 부드러운 가감속까지 |
| 음악이 정확히 붙는가 | **된다** — 48 kHz 그대로, 프레임 단위 |
| 한글 자막 | **나온다** |
| 유튜브 규격 | **H.264 1080p30 AAC 로 바로 나온다** |
| 렌더 시간 | 8초 영상에 **30초쯤** → 10분이면 **40분 안팎으로 추정** |
| 라이선스 | **개인은 상업적 이용도 무료** (4명 이상 조직만 유료) |

**시험한 것** — `산출물/20260823 - G3 판정 자를 먼저 만든다/Remotion 시험 - 켄번스 8초.mp4`

### 5.2 AI 영상 생성과 경쟁하지 않는다 — 층이 다르다

| | 무엇을 하나 |
|---|---|
| **AI 생성** (Kling 등) | **사진 한 장을 3~5초 살아 움직이게** — 물이 흐르고 구름이 지나간다 |
| **Remotion** | **그 클립들과 정지 사진을 엮어 10분짜리로** — 배치·전환·자막·타이밍 |

**AI 생성이 재료를 만들고 Remotion 이 조립한다.**

### 5.3 그리고 안전망이 생겼다

[`02`](<02. AI 영상 생성 기술 검증 계획서.md>) 4장이 G3 실패 시나리오를 **「켄번스로 회귀」**라고 적어 뒀다. **그것이 더 이상 초라한 후퇴가 아니다** — Remotion 의 켄번스는 기본기이고, **음악에 정확히 맞춘 244장짜리 다큐멘터리식 영상**은 그 자체로 완성품이 된다.

### 5.4 AI 생성 도구 — 조사했다. **아직 사지 않았다** (2026-08-23)

> **검수자** — *"멋진 동영상 만들려면 사용할 수 있는 도구는? 이런 것 어때?"*
> (Seedance 2.5 · PixVerse MCP 자료를 주시며)

#### (1) 먼저 — **주신 자료 두 개는 서로 다른 회사다**

| | 만드는 곳 | 무엇 |
|---|---|---|
| **Seedance 2.5** | **ByteDance** (틱톡) | 영상 생성 **모델**. 2026-07-31 공개 · **API 는 8월 7일에 열렸다** |
| **PixVerse** | **AIsphere** (다른 회사) | 영상 생성 **서비스**. 자체 API 와 MCP 를 낸다 |

**한 제품의 두 이름이 아니다.** 자료가 둘을 나란히 실어서 그렇게 보였다.

#### (2) **PixVerse MCP 는 우리에게 안 맞는다 — 사진을 못 받는다**

`MCP` 는 **Claude 가 바깥 서비스를 직접 부르게 해 주는 연결선**이다. 붙이면 내가
「이 사진을 5초 영상으로」라고 시킬 수 있다 — **원래 그럴 줄 알았다.**

**그런데 공식 문서가 아니라고 못박고 있다.**

| | PixVerse **MCP** | PixVerse **API** |
|---|---|---|
| 글 → 영상 | 된다 | 된다 |
| **사진 → 영상** | **안 된다** | **된다** |

> 공식 FAQ — *"Not yet. These features are only available via the PixVerse API."*

**우리는 2005년 사진을 움직이게 하는 것이 전부다.** 글로 새 장면을 지어내는 것은
[`00`](<00. 스페인 전람회의 그림 기획서.md>) V2(배경 변경 금지)가 막는다. **MCP 는 쓸 일이 없다.**

> **★ 그런데 이것이 나쁜 소식이 아니다.** **API 열쇠만 있으면 MCP 없이 내가 직접 부른다.**
> 오히려 붙일 것이 하나 줄었다.

#### (3) 값 — **PoC 8건은 둘 다 $20 안에 든다**

| | 5초 한 편 | **PoC 8건** | 어떻게 사나 |
|---|---|---|---|
| **PixVerse API** | **$0.30~0.45** | **$3~4** | 선불 충전 · **$10 부터** |
| **Seedance 2.5** (OpenRouter 경유) | **$0.51** (480p) · 해상도 올리면 비싸진다 | **$4~10** | 쓴 만큼 |

**둘 다 상한($20) 의 절반 아래다.** 다만 **실패한 생성도 돈이 나간다** — 다시 뽑는
횟수가 값을 정한다. 그래서 [`02`](<02. AI 영상 생성 기술 검증 계획서.md>) 가 8건으로 못박아 둔 것이다.

#### (4) **아직 확인 못 한 것 넷 — 사기 전에 봐야 한다**

**적어 두는 이유는 「모르는 것을 아는 것처럼 보고하지 않기 위해서」다.**

| # | 무엇 | 왜 걸리나 |
|---|---|---|
| 1 | **1024×768 저해상도 사진을 받는가** | 우리 사진이 그 크기다. 안 받으면 **업스케일이 먼저**가 된다 |
| 2 | **상업적 이용·크레딧 표기 의무** | `CLAUDE.md` 저작권 절이 요구하는 확인. 도구마다 다르다 |
| 3 | **같은 사진으로 다시 뽑으면 같은 것이 나오는가** | 안 나오면 **생성물을 반드시 보관**해야 한다(BL-28 과 같은 조건) |
| 4 | Seedance 2.5 가 **실제로 열려 있는가** | 8월 7일 개통이라 적혀 있으나 **직접 부르기 전에는 모른다** |

#### (5) **그런데 도구보다 먼저 정할 것이 있다**

**7장 미결의 「어디까지 생성할 것인가」가 도구를 정한다.** 순서가 반대면 헛돈이다.

| 어디까지 | 필요한 성질 | 어울리는 것 |
|---|---|---|
| **사진에 있던 것만 움직인다** (물·구름·사람 그림자) | **시키는 대로만 하는 얌전함** | Kling · PixVerse |
| **없던 것을 그려 넣는다** (그녀의 실루엣이 걸어온다) | **그럴듯하게 지어내는 힘** | Seedance 2.5 |

**우리 합격선이 「사진을 배신하지 않을 것」이다** — 첫 프레임이 원본과 0.90 이상
닮아야 하고 건물 직선 수가 ±15% 안이어야 한다([`02`](<02. AI 영상 생성 기술 검증 계획서.md>) 4장).
**멋지게 지어내는 힘이 셀수록 이 시험에서는 불리하다.** 자를 오늘 만들어 둔 이유가 그것이다.

## 6. 작업 순서

**「뼈대 먼저」가 원칙이다.** 사진을 다듬거나 AI 로 움직이게 하는 것은 **어디에 몇 초 놓을지가 정해진 다음**이다.

| # | 무엇 | 왜 이 순서인가 | 상태 |
|---|---|---|---|
| **1** | **★ 10분 뼈대** — 악장 열 개에 사진을 배분하고 음악을 통째로 얹는다 | **여기서 「사진마다 몇 초, 어떤 크기」가 나온다.** 그게 없으면 뒤가 다 추측이다 | **다음 작업** |
| 2 | **프롬나드 넷을 채운다** | 202초가 비어 있다 | 4장 미결 |
| 3 | **셀렉** — 어느 사진을 쓰나 (A/B/C) | 뼈대에서 「몇 장 필요」가 나온 뒤 | WBS 2.1 재개 |
| 4 | **업스케일** — 필요한 것만 필요한 배율로 | **뼈대가 배율을 정한다.** 지금 하면 두 번 일한다 | WBS 2.3 |
| 5 | **G3 PoC** — AI 생성을 쓸지 | 뼈대와 병렬로 가능 | WBS 2.2 |

### 6.1 업스케일을 왜 나중에 하나

**「이 사진을 화면에 어떻게 놓을지」가 정해져야 필요한 크기가 나온다.**

| 그 사진을 | 필요한 배율 |
|---|---|
| 화면에 꽉 채우고 켄번스로 1.15배 더 | **2.16배** |
| 화면에 꽉 채우기만 | 1.88배 |
| **멀티패널로 세 장 중 하나** | **0.7배** (오히려 축소) |
