## 1. 먼저 「함수」가 무엇인가

**함수는 「이름 붙인 절차」입니다.**

요리로 치면 **레시피**입니다. 「육수 내는 법」을 한 번 적어두고, 국을 끓일 때마다 그 레시피를 부릅니다. 매번 처음부터 다시 적지 않습니다.

코드로 보면 이렇습니다.

```python
def db(x):                      # ← 이름: db
    r = 제곱평균제곱근(x)         # ← 절차
    return 20 * log10(r)        # ← 돌려주는 것
```

이제 어디서든 `db(소리)` 라고 쓰면 **그 세 줄이 통째로 실행됩니다.**

| | |
|---|---|
| **이름** | `db` |
| **받는 것** | 소리 데이터 |
| **돌려주는 것** | 데시벨 숫자 |

---

## 2. 「공용」 함수는 무엇이 다른가

**한 파일 안에서만 쓰는 함수**가 있고, **여러 파일이 같이 쓰는 함수**가 있습니다. 뒤쪽을 **공용 함수**라고 부릅니다.

```
        화성.py  ← 여기에 한 번 적는다
           │
     ┌─────┼─────┬─────────┐
     ↓     ↓     ↓         ↓
 검증화성  악장대조  주역교대   전곡화성      ← 넷이 같은 것을 부른다
```

**이 프로젝트에서는 `화성.py` 가 그 창고입니다.** 화음 배치·베이스 생성·잔향·콘솔 같은 것이 거기 있고, 나머지 스크립트가 갖다 씁니다.

> **비유** — 식당 주방에 **육수 솥**이 하나 있고, 국수도 찌개도 전골도 거기서 퍼다 씁니다. 요리마다 따로 육수를 내면 **맛이 조금씩 달라집니다.**

## 3. 오늘 왜 하나 더 만들었나 — 실제로 사고가 났다

### 3.1 무슨 일이 있었나

**오늘 마스터 파일을 16비트에서 32비트로 올렸습니다**([10](<10. 렌더와 음원 파일 — 소리가 만들어져 파일이 되기까지.md>)). 소리는 그대로였습니다.

**그런데 검증 도구를 돌리니 이렇게 나왔습니다.**

```
[악장별 RMS / dB]
  0 프롬나드 제시      -109.9 dB      ← 정상은 −17 근처
  6 론다           -115.4 dB
  9 대문           -108.2 dB
```

**−110 dB 는 사실상 무음입니다.** 곡이 통째로 안 들린다는 뜻인데, **실제로 틀어보면 멀쩡했습니다.**

### 3.2 원인 — 「이 숫자가 무슨 단위인가」를 안 물었다

파일에서 소리를 읽는 함수(`wavfile.read`)는 **파일에 적힌 형식 그대로** 돌려줍니다.

| 파일이 | 돌려주는 숫자의 범위 |
|---|---|
| 16비트 | **−32768 ~ 32767** (정수) |
| 32비트 실수 | **−1 ~ 1** (실수) |

**도구 세 개가 전부 「32768로 나눈다」고 박아놓고 있었습니다.** 16비트일 때는 맞습니다. 그런데 파일이 32비트 실수로 바뀌니 **이미 −1~1인 값을 또 32768로 나눠** 3만 배 작아졌습니다.

```python
x = x.astype(np.float64) / 32768.0     # ← 세 파일에 똑같이 박혀 있었다
```

### 3.3 제일 나쁜 부분 — 어제 같은 실수를 하고 회고까지 썼다

**2026-08-11에 똑같은 일이 있었습니다.** 스템 파일(float32)을 int16으로 읽어 **−118 dB** 를 얻었고, 그때 저는 「스템이 비었나」로 갔지 「내가 잘못 읽었나」로 안 갔습니다.

그날 회고에 이렇게 적었습니다.

> **"숫자를 읽기 전에 「이게 무슨 단위인가」를 묻는다. 오늘 여섯 번이면 우연이 아니다."**

**적어놓기만 하고 도구는 안 고쳤습니다.** 그래서 하루 만에 다시 났습니다.

> **이것이 공용 함수를 만드는 진짜 이유입니다.** 규칙을 문서에 적으면 **다음에 스크립트를 새로 쓸 때 또 틀립니다.** 함수로 만들면 **부르는 것만으로 지켜집니다.**

### 3.4 만든 것

`화성.py` 에 **`read_wav()`** 를 만들고 네 스크립트가 그것만 쓰게 했습니다.

```python
def read_wav(path):
    sr, a = wavfile.read(path)
    if a.dtype.kind == "i":           # 정수면 최대값으로 나눈다
        a = a / np.iinfo(a.dtype).max
    else:                             # 실수면 이미 −1~1 이다
        a = a.astype(np.float64)
    return sr, a
```

**「무슨 형식인지 먼저 보고 그에 맞게 나눈다」**가 전부입니다. 세 줄입니다.

**고친 뒤**

```
  0 프롬나드 제시       -19.6 dB      ← 정상
  6 론다            -25.1 dB
  9 대문            -17.9 dB
```

**덤이 하나 있습니다** — 이제 **16비트 기준선과 32비트 새 렌더를 나란히 대조**할 수 있습니다. 형식이 서로 달라도 됩니다. 전에는 둘 중 하나가 틀리게 읽혔습니다.

## 4. 이 프로젝트의 공용 함수들

**`화성.py` 가 창고입니다.** 주요한 것만 적습니다.

| 이름 | 하는 일 | 왜 공용인가 |
|---|---|---|
| **`read_wav`** | **wav 를 읽어 −1~1 로 맞춘다** | **오늘 신설.** 네 도구가 같은 실수를 했다 |
| `voice_lead` | 화음의 음들을 **어느 높이에 놓을지** 고른다 | 악장마다 부른다. 규칙이 하나여야 한다 |
| `bassline` | 화음음 사이를 걷는 베이스를 만든다 | 같다 |
| `room` · `plate` | 울림을 건다 | 같은 공간이어야 한다 |
| `Desk` | 여덟 갈래를 담는 콘솔 · 스템 입출력 | 렌더와 믹스가 같은 그릇을 써야 한다 |
| `lay_drum` · `pat_*` | 드럼 패턴을 놓는다 | 악장마다 부른다 |

**`piano.py` · `ensemble.py` · `synth.py`** 는 **악기 창고**입니다 — 피아노·현악·기타·베이스·해먼드·무그·드럼 소리를 만드는 함수들이 거기 있습니다.

## 5. 언제 만들고 언제 안 만드나

**공용으로 만드는 것이 항상 옳지는 않습니다.**

| 만든다 | 안 만든다 |
|---|---|
| **두 곳 이상에서 똑같이 쓴다** | 한 곳에서만 쓴다 |
| **틀리면 조용히 틀린다** (오늘의 `read_wav` 같은 것) | 틀리면 바로 터진다 |
| **규칙이 하나여야 한다** (같은 화음이 파일마다 다르게 배치되면 안 된다) | 파일마다 달라도 되는 것 |
| 앞으로 새 스크립트가 또 쓸 것 | 이번 한 번만 |

> **핵심은 「두 번 적었나」가 아니라 「어긋나면 문제가 되나」입니다.**
>
> 이 프로젝트의 제1 경고가 **「같은 사실이 두 곳에 있으면 반드시 어긋난다」**인데(`CLAUDE.md` 2절), **그건 문서 이야기이면서 코드 이야기이기도 합니다.**

**반대로 지나치면 이렇게 됩니다** — 함수 하나가 온갖 경우를 다 처리하려다 옵션이 열 개가 되고, 결국 아무도 못 읽게 됩니다. **`read_wav` 가 세 줄인 것이 좋은 신호입니다.**

## 6. 규칙 — 앞으로 이렇게 한다

1. **wav 를 읽을 때는 반드시 `화성.read_wav` 를 쓴다.** `wavfile.read` 를 직접 부르지 않는다
2. **같은 계산이 두 파일에 생기면 그 자리에서 옮긴다.** "나중에"는 안 온다
3. **문서에 규칙을 적었으면 「도구가 대신 지킬 수 있는가」를 묻는다.** 지킬 수 있으면 도구로 옮긴다

> **3번이 오늘 배운 것입니다.** 어제 「단위를 묻는다」를 회고에 적고 도구는 안 고쳤고, **하루 만에 같은 사고가 났습니다.**
>
> 이 프로젝트에 이미 같은 판단이 여럿 있습니다 — `악장표.py`(악장별 사실을 손으로 안 적는다) · `검증.py`(문서 정합성을 사람이 안 본다) · `납품.py`(음원 형식을 손으로 안 굽는다). **셋 다 사고가 난 뒤에 만들어졌습니다.**

## 7. 한 줄 정리

| 질문 | 답 |
|---|---|
| **함수가 뭔가** | **이름 붙인 절차.** 레시피 |
| **공용 함수가 뭔가** | **여러 파일이 같이 쓰는** 함수. 이 프로젝트는 `화성.py` 가 창고 |
| **왜 쓰나** | 같은 것을 여러 곳에 적으면 **반드시 어긋나기** 때문 |
| **오늘 무슨 일이 있었나** | 마스터를 32비트로 올렸더니 **도구 셋이 −110 dB** 를 찍었다. 「32768로 나눈다」가 세 곳에 박혀 있었다 |
| **제일 뼈아픈 부분** | **하루 전에 같은 실수를 하고 회고까지 썼는데 도구는 안 고쳤다** |
| **그래서 뭘 배웠나** | **문서에 적을 수 있는 규칙은 도구로 옮길 수 있는지 먼저 묻는다** |
