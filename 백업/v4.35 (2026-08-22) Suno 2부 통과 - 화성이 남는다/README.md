## 이 저장소에 없는 것

**음원·영상·사진은 여기 없다.** git은 한 번 넣은 바이너리를 영원히 기억하므로 저장소가 계속 무거워지고, 검토 영상 한 편(114 MB)은 GitHub의 파일 크기 한도를 넘는다.

| 무엇 | 어디에 |
|---|---|
| 납품 음원 · 검토 영상 | **Google Drive** — `산출물/<날짜>/README.md` 에 링크와 설명이 있다 |
| 원본 사진 253장 · 플라멩코 MOV 9편 | 로컬 `2005년 12월 스페인/` |
| 참고 악보 | 로컬 `자료/` (저작권 있는 편곡 스캔 포함) |
| 렌더 산출 wav · 스템 1.4 GB | 로컬. **코드를 돌리면 다시 생긴다** |

**"무엇이 있었는가"는 이 저장소가 알고, "그 파일"은 Drive에 있다.**

## 왜 코드 이력이 중요한가

이 프로젝트의 렌더는 **비트 단위로 재현된다** — 같은 코드를 두 번 돌리면 100.0000% 같은 wav가 나온다(BL-30, 2026-08-07). 그래서 음원은 원리적으로 "다시 만들 수 있는 것"이다.

**단, 코드가 남아 있을 때만 그렇다.**

2026-08-08까지 이 프로젝트에는 git이 없었고 `백업/`은 마크다운만 담았다. 그래서 **G2 승인 음원을 만든 코드가 어디에도 없다.** 이 저장소는 그것을 푼다.

두 가지는 코드가 있어도 반드시 보관한다.

1. **검수 판정 대상 음원** — "무엇을 듣고 승인했는가"의 물증
2. **외부 도구 생성물** (BL-28 보컬) — 자체 합성과 달리 **원리적으로 재현이 안 된다**
