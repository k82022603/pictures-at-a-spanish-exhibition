## 3. ★ 0:02~0:30 잡음 — 검수자가 잡았다

> *"잇기 다시 해봐 0:02~0:30 까지 소음(잡음)"*

**Suno `Extend` 는 화면에 `KEEP`(0~43초) 라고 적어놓고 그 구간도 재합성한다.**

| 0:02~0:30 | 고역 4 kHz↑ | 초고역 10 kHz↑ |
|---|---|---|
| 원본 0악장 Suno-02 | −20.0 dB | −26.8 dB |
| **Extend 결과** | **−36.5** | **−51.9** |

**고역이 최대 23 dB 깎여 나갔다.** 30초 뒤부터는 멀쩡하다.

**해법** — 원본을 39.0초까지 쓰고 종결만 Extend 에서. **이음매는 30~43초를 0.5초마다 훑어 두 소리가 가장 닮은 자리**를 골랐다(종합 4.29, 다음이 4.66).

**그러면서 드러난 것** — **파형 닮음이 13초 어디에서도 0.2 를 못 넘는다.** Suno 는 `KEEP` 을 복사한 게 아니라 **같은 곡을 다시 연주했다.**

## 5. ★ 16비트 사고 — `납품.py` 가 잡았다

> ⚠ 마스터가 **s16** 이다. 32비트로 못 간다

`꼬리늘리기.py` 의 `쓰기()` 가 **`np.int16`** 으로 저장하고 있었다.

| | |
|---|---|
| Suno 원본 | **16비트** — 그래서 정보를 깎은 것은 아니다 |
| 문제 | **우리가 더한 것**(잔향 꼬리·크로스페이드)**이 16비트로 양자화됐다.** 꼬리 끝 −85 dB 에 16비트 바닥 −96 dB — **여유 11 dB** |
| 증거 | 같은 32비트 FLAC 이 **16비트 원본에서 64.4 MB, float 원본에서 170.4 MB** |

**float32 로 다시 만들었고, 16비트판은 `잘못 만든 것 - 16비트판/` 으로 옮겼다**(R11).

**그리고 `전곡잇기.py` 가 이제 `ffprobe` 로 낸 파일의 자료형을 본다.**

### 5.1 잘못 진단했다가 정정한 것

FLAC 을 되돌려 대조했더니 −219.1 dB 차이가 나서 **「fftconvolve 가 실행마다 다르다」**고 진단했다. **틀렸다.** 두 번의 비교가 **정확히 같은 값**(−219.1 dB · 다른 표본 187415개)이었고, **같다는 것이 곧 재현된다는 뜻**이었다.

**차이의 정체는 float32 ↔ 32비트 정수 변환의 반올림**이고, FLAC 은 정수 형식이라 불가피하다. **24비트 잡음 바닥(−144 dB)보다 75 dB 아래.**
