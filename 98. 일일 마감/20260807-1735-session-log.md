**운율 규칙이 언어마다 다르다.** 한국어는 음절 박자 언어라 11음절을 `[4][3][4]`로 끊으면 됐지만, 영어는 강세 언어이므로 **긴 음(1·2·3·6·9·10·11박)에 강세 음절**을, **짧은 8분음표 쌍(4·5, 7·8)에 강약 2음절어**를 놓는다.

초안 여덟 행을 `07` 11장에 남겼다. **4행은 놓을 자리가 없다** — 0악장 0:30.7~0:50의 19.3초 주제 공백. 1.4.1에서 주제를 한 번 더 놓으면 들어간다.

### v1.17 — 목소리 처리 기준 · BL-29 신설

검수자가 Greg Lake 창법을 MIDI로 흉내내는 기법 일곱 가지를 참고로 건넸다. **나는 그것을 "외부 도구 대신 악기로 목소리를 만들자"는 제안으로 잘못 읽고 앞선 결정과 충돌한다고 적었다.**

두 가지는 같은 층의 선택지가 아니다 — 앞의 것은 **무엇으로 만드는가**(외부 도구), 뒤의 것은 **어떻게 다루는가**(타이밍·다이내믹·음색·잔향). 일곱 중 둘(레가토·비브라토)만 도구 소관이고 **나머지 다섯은 목소리가 어디서 왔든 적용된다.**

코드와 대조한 결과:

| | 상태 |
|---|---|
| 글라이드 | `moog(glide_from=)` — 있음 |
| 지연 비브라토 | `ensemble.py:48`에 **이미 구현** (0.25초 뒤부터 0.5초에 걸쳐 차오름). 현악에만 |
| 레이드백 타이밍 | 없음 — `H()`가 평균 0이라 앞뒤로 흔들릴 뿐 늦지 않는다 |
| 지속음 크레셴도 | 없음 |
| **플레이트 잔향** | **막힘 → BL-29 신설** |

**BL-28 음색 판정 기준도 명시했다** — "조잡하면 탈락"뿐이던 것을 **로우미드 200~500Hz 실측**으로.

## 세션 6 — BL-29 스템 분리 (v2.1)

### 환경 실측

| | 값 |
|---|---|
| 이 PC | 15.7 GB (여유 7 GB) |
| 7스템 스테레오 float32 | **1.35 GB** |
| 실제 저장 | **1.33 GB** |

### 단계 1 — 구조만 교체

`Desk(stems=)` 신설. 옛 단일 버퍼 경로는 `stems=False`로 남겼다. 페이더를 믹스 시점으로 옮기며 죽어 있던 `mix(gains=)`를 살렸다. `_Send.put` 시그니처는 안 건드려서 악보 500여 줄 무수정.

```

Desk 단위 검사 — mix() 통과 후    −125.2 dB
```

### 단계 2 — 성부별 잔향 · plate()

`mix(sends=)` 추가. `sends=None`이면 이전과 **100.0000% 비트 일치**.

무그에만 플레이트를 건 시험 — **무그가 있는 4·7·8·9악장만 움직였다**(−25 ~ −33 dB). 나머지는 −58 dB로 사실상 무변화(마스터 정규화가 미세하게 이동). **센드가 새지 않는다.**

> 이 시험으로 무그가 **8악장에도** 편성돼 있음을 확인했다. 이전에는 4·7·9로 알고 있었다.

### 단계 3 — 스템 디스크 저장

## 세션 6 중 발견 — 렌더가 재현되지 않았다 (BL-30)

**오늘 가장 값이 큰 발견이다.**

단계 1 검증에서 옛·새 경로 차이가 **−56.3 dB**로 나왔다. 예상은 −140 dB였다. 단위 검사는 −128 dB인데 전곡은 −56 dB라 설명이 안 됐다.

**그럴듯한 이야기를 만들지 않고 나눠 쟀다.** 같은 설정으로 두 번 렌더해 비교했다.

```
같은 코드 · 같은 설정 · 2회 렌더
  완전 일치 샘플  91.47%
  차이 RMS       2.181e-04     ← 스템 대조와 같은 값
```

**스템 분리는 아무 차이도 만들지 않았다. −56 dB는 전부 렌더 자체의 비재현성이었다.**

### 원인

`synth.py`가 씨앗 없는 전역 난수(`np.random`)를 **여덟 곳**에서 쓴다. 곡에 실제로 쓰이는 것은 둘.

| 위치 | 무엇 |
|---|---|
| `ladder_nl` 203행 | **무그 열잡음** — BL-24b 자기발진의 씨앗 |
| `hammond` 277행 | **해먼드 키클릭** |

시간 분포가 증명한다 — 오르간이 셀수록 차이가 크다.

| 구간 | 차이 | 편성 |
|---|---|---|
| 0~58초 (0악장) | −68.8 dB | 오르간 `org=0.16`, 무그 없음 |
| 116~174 (3악장) | **−54.4** | **오르간 코랄 `org=0.90`** |
| 290~348 (6악장) | −65.3 | `org=0.10`, 가장 조용 |
| 464~522 (8악장) | **−52.1** | **오르간+무그 총주** |

### 고침

`ladder_nl(seed=)`·`hammond(seed=)` 추가, `화성.py`의 `_seed()`가 캐시 키에서 씨앗을 접는다. **파이썬 `hash()`는 쓰지 않았다** — 문자열 해시 무작위화 때문에 그것도 실행마다 다르다. `hamm`의 캐시 키가 쓰던 `id(reg)`(메모리 주소)도 `tuple(reg)`로 바꿨다.

```
고친 뒤 — 같은 코드 2회 렌더
  완전 일치 샘플  100.0000%
  최대 절대차     0 LSB
```

**지표는 하나도 안 움직였다.** 조성 밖 음 10개 · 대역 7개 · 악장별 RMS 10개 · 경직됨 0.955 · 9:26 F♯ 0.136 — 서른 개 넘는 값이 소수점 셋째 자리까지 동일. **넉 달 동안 지표 해상도 아래에 있었다.**

**BL-31 신설** — `synth.py`에 씨앗 없는 난수 여섯 곳(드럼·`bass()`)이 남아 있다. 지금 곡엔 안 쓰이지만 **1.1.6 드럼 재설계에서 살아난다.**

## 세션 7 — 잔향 판정과 설명 지침 (v2.2)

### plate() 재작성

처음 만든 것은 **꼬리가 0.4초**뿐이라 "다른 공간"으로 안 들렸다. 탭을 겹치는 방식으로는 밀도와 길이를 동시에 못 얻는다(수백 번 더해야 한다).

**감쇠하는 잡음을 임펄스 응답으로 삼아 합성곱**하는 방식으로 바꿨다. `sg.oaconvolve`. rt60 2.0초, 고역 7.6kHz, 프리딜레이 14 ms. 잡음이 곧 최대 밀도다.

### 무그가 가장 드러나는 자리 — 스템으로 찾았다

렌더 없이 스템만 읽어 1초 창으로 lead 대 전체 비를 쟀다.

```
411~416초 (6:51~6:56)  전체 대비 최고 −3.3 dB   ← 가장 노출
344~349 (5:44~5:49)   −3.6 dB
363~368 (6:03~6:08)   −3.8 dB
```

데모 구간을 **404~426초**로 잡았다. 무그 프레이즈 사이에 빈 자리가 있어 꼬리가 들린다.

### 2×2 실측 — 빠진 조합을 만들어 갈랐다

검수자가 C(밴드 드라이 + 무그 흠뻑)를 좋다고 해서, **변수 둘이 섞여 있으므로** 빠진 조합 D(밴드만 드라이)를 만들었다.

| | 경직됨 | 로우미드 | 프레즌스 | RMS 폭 | A 대비 악장별 |
|---|---|---|---|---|---|
| **A** 현행 | 0.955 | −4.2 | −11.2 | 5.8 | — |
| **B** 무그 젖음 (0.85) | 0.949 | −4.1 | −11.3 | 6.1 | +0.0 ~ +0.3 |
| **C** 둘 다 | **0.946** | −4.0 | −11.3 | 6.3 | −1.0 ~ −1.8 |
| **D** 밴드만 드라이 | 0.956 | −4.2 | −11.2 | 5.8 | **±0.0 전부** |

**D가 A와 사실상 같다.** 전역 잔향을 0.15 → 0.02로 내렸는데 열 악장이 전부 ±0.0 dB다. **좋게 들린 것은 플레이트였다.** 지금 걸린 룸 잔향은 거의 일을 안 하고 있다.

플레이트는 **경직됨을 낮춘다** (0.955 → 0.946). 잔향이 2~4kHz 포락선을 부드럽게 한다.

**무그 플레이트 1.0을 기본으로.** 그리고 "필요한 곳에서는 더 극대화해도 되지 않나, 악기에 따라 달라지지 않나"라는 물음이 나왔다.
